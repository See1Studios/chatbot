# UX 껍데기 로드맵 — 메신저 먼저, 데스크톱 캐릭터는 두 번째 껍데기

> 방향 (align/D, 2026-09-29): **핵심** — 메신저는 관계 고리를 검증하는 기본 UX이고, 데스크톱 캐릭터는 CONCEPT가 정체성으로 둔 「움직이는 데스크톱 동반자」다. 둘의 순서와 경계를 정한다

> 상태: **active** (2026-09-29 초안)
> 목적: 메신저 UX를 먼저 "완성"하고 데스크톱 캐릭터 UX로 넘어가는 순서를 채택하되, ① 메신저 "완성"을 끝이 있는 기준으로 정하고 ② 엔진을 화면에서 떼어 두 껍데기가 같은 통로를 쓰게 하고 ③ 캐릭터 중심 밀도를 다리로 삼는다.

## 1. 운영자 제안 (2026-09-29)

"나중에 데스크탑 캐릭터 형태의 UX를 추가할 예정이지만 기본 UX는 메신저 형태. 메신저 형태를 완성한 후 캐릭터 UX에 들어가는 계획 어때?" → 조건부 찬성 후 "계획 문서로 정리해줘".

이어서: "메신저 측면에서 UX는 Telegram, Line, Kakaotalk 등의 Modern Messenger 앱을 따라가는 수준까지 다듬어야 해." → 4.2의 기준선.

## 2. 판단

**순서는 채택한다.** 대화·기억·선택지·호감도 같은 관계 고리는 메신저에서 검증하는 편이 가장 싸다. 데스크톱 캐릭터에 필요한 재료(투명 스프라이트, 표정 대체 사슬, 그림 관리)도 메신저 작업 중에 쌓인다.

**그대로 두면 생기는 위험 두 가지:**

1. **데스크톱은 부속물이 아니다.** CONCEPT는 「움직이는 데스크톱 동반자」와 「Steam에 BYOK 데스크톱 동반자로 먼저 이름을 박는다」를 정체성으로 둔다. 시장 검토도 차별점을 "대화창 안에서 못 하는 것 = 데스크톱 형식"으로 본다. 메신저만으로는 제타·SillyTavern류와 겉모습이 겹친다. 그래서 순서는 뒤라도 날짜 없는 "언젠가"가 되면 안 된다.
2. **"완성"에 끝이 없다.** UI 다듬기는 끝나지 않는다. 기다리는 동안 채팅 화면(DOM)을 전제로 한 코드가 쌓이면 데스크톱을 붙일 때 뜯어고쳐야 한다.

## 3. 현황 (2026-09-29 코드 기준)

- **외형 통로는 있다.** `static/visual-adapter.js`의 `VisualAdapter`(`load`·`setEmotion`·`speak`·`destroy`)와 `AdapterRegistry`, 구현체는 `static/visual-sprite-adapter.js` 하나.
- **감정은 서버 이벤트다.** `emotion.py`가 답변의 표정 태그를 읽어 턴마다 `{"type":"emotion"}` SSE(서버가 브라우저에 밀어 주는 이벤트 흐름) 하나를 보낸다(`server.py`).
- **배달은 채팅 페이지에 묶여 있다.** `static/app-characters.js`가 브라우저의 `EventSource`를 가로채서 감정을 어댑터로 넘긴다. 이벤트 흐름도 세션 단위(`/api/sessions/<sid>/events`)다. 채팅 페이지를 열지 않은 데스크톱 껍데기는 지금 캐릭터 상태를 받을 길이 없다.
- `align/K`(게임 속 메신저 적용)는 대기 상태이고, 수용 기준은 "§5.1의 가르는 선 세 가지가 화면에 있고 테마 7종이 동작"이다.

## 4. 설계

### 4.1 두 껍데기, 하나의 엔진

식당으로 치면 주방(엔진)은 하나이고 홀(메신저)과 배달(데스크톱)이 창구다. 창구는 주방에 **정해진 주문서(이벤트)**로만 말하고, 주방은 어느 창구에서 온 주문인지 모른다.

- **캐릭터 상태 이벤트**: `emotion`·`speaking`(시작/끝)·`action`(지문)·`presence`(대기/생각 중/자리 비움)를 엔진이 캐릭터 단위로 낸다. 메신저와 데스크톱 모두 같은 이벤트를 구독한다.
- **화면 쪽 규칙**: 캐릭터 연출 코드는 `VisualAdapter`만 부르고 채팅 DOM(말풍선·로그)을 읽지 않는다. 반대로 채팅 코드는 스프라이트를 직접 만지지 않는다.
- **집행자**: 이 규칙은 테스트로 막는다(`ux/C`). `visual-*.js`가 채팅 DOM 선택자를 참조하거나 `EventSource` 가로채기가 새로 생기면 실패한다.

### 4.2 메신저 "완성"의 정의

메신저 완료 = 아래 체크리스트가 모두 참일 때. 이후의 다듬기는 데스크톱 작업과 **병행**하고 선행 조건으로 삼지 않는다.

1. **현대 메신저 기준선**(4.2.1)을 모두 통과한다.
2. `align/K`의 수용 기준(가르는 선 세 가지: 캐릭터가 대화에 끼어듦, 관계가 보임, 캐릭터별 개인화가 묻어남 + 테마 7종).
3. 세 밀도(① 캐릭터 중심 ② 심플 ③ 어드밴스드)를 오갈 수 있다.
4. 보스 키(순식간에 숨기기)가 동작한다.
5. 캐릭터 연출이 모두 4.1 이벤트로 돈다(`ux/B`·`ux/C` 완료).

#### 4.2.1 현대 메신저 기준선 (운영자 2026-09-29: Telegram·LINE·KakaoTalk 수준)

**기준은 "손에 익은 동작과 매끄러움"이지 모양이 아니다.** 사용자가 메신저에서 이미 익힌 동작은 그대로 동작해야 한다. 반면 겉모습은 D10(게임 속 메신저, 특정 앱 모양을 베끼지 않음, 평범한 채팅앱은 버림)을 따른다. 이 둘은 충돌하지 않는다. 기준선은 바닥이고, 게임 속 메신저가 그 위에 얹는 개성이다.

끝이 있게 하려고 목록으로 고정한다. 목록에 없는 것은 기준선이 아니다. 항목마다 세 앱 중 두 곳 이상이 가진 동작만 넣었다.

| 영역 | 기준선 동작 |
|---|---|
| 목록 | 대화방 목록(마지막 메시지 미리보기·시각·안 읽은 수), 고정, 검색 |
| 대화 흐름 | 날짜 구분선, 같은 사람 연속 메시지 묶기, 보낸 시각, 읽음·입력 중 표시, 안 읽은 곳으로 이동·맨 아래로 버튼, 위로 스크롤하면 이전 대화 불러오기 |
| 메시지 동작 | 길게 누르기/우클릭 메뉴(답장·복사·삭제·다시 보내기), 답장(인용) 표시와 원문으로 이동, 반응(이모지), 실패 표시와 재전송 |
| 입력 | 여러 줄 입력과 Enter 규칙, 임시 저장(방을 나갔다 와도 남음), 붙여넣기·끌어다 놓기 첨부, 이모지·스티커 서랍 |
| 미디어 | 그림 미리보기와 전체 화면 보기(확대·넘기기), 링크 미리보기 |
| 대화 안 검색 | 방 안 검색과 결과로 이동 |
| 알림 | 다른 창일 때 브라우저 알림, 탭 제목의 안 읽은 수 |
| 몸감(feel) | 모바일 폭·키보드가 올라와도 입력창이 가려지지 않음, 보낸 메시지가 바로 뜸(낙관적 표시), 스크롤이 튀지 않음, 전환 애니메이션 200ms 안팎, 키보드만으로 조작 가능 |

**기준선이 아닌 것**: 음성·영상 통화, 채널·단체방·봇 플랫폼, 여러 기기 동기화, 종단 간 암호화, 스티커 상점. 동반자 제품에 필요해지면 따로 계획한다.

진행 방식: `ux/I`가 이 표를 현재 화면과 대조해 있음/부분/없음을 매긴다(갭 감사). 빈 칸이 `ux/D`의 쪼갠 티켓이 된다.

### 4.3 다리: ① 캐릭터 중심 밀도를 앞당긴다

① 캐릭터 중심(캐릭터 + 말풍선)은 브라우저 안에서 하는 데스크톱 예행연습이다. 투명 스프라이트, 표정 전환, 말할 때의 연출, 대기 동작을 여기서 먼저 검증하면 데스크톱 껍데기는 "창을 바꾸는 일"로 줄어든다.

### 4.4 데스크톱 기술 스파이크 (짧게, 먼저)

스파이크 = 버릴 각오로 짧게 만들어 보는 기술 시험. 메신저 완료를 기다리지 않고 기간을 정해 한 번 한다. 확인할 것:

- 투명·항상 위·클릭 통과 창을 Windows/macOS에서 띄울 수 있는가, 어떤 셸(Tauri·Electron·기타)이 가벼운가.
- **엔진 위치**: 배포판은 사용자 PC에서 엔진이 돈다. 개발판은 엔진이 NAS에 있다. 데스크톱 껍데기가 둘 다에 붙는 연결 방식(로컬 주소·인증)을 정한다.
- 4.1 이벤트를 받아 스프라이트 하나가 표정을 바꾸는 데까지.

선행 사례는 스파이크 전에 조사한다(`~/AGENTS.md` §0 prior art): VPet(Steam, 오픈소스), Desktop Mate, Shimeji 계열, Wallpaper Engine의 위젯·오버레이. 가져올 것/버릴 것 표로 정리한다.

## 7. 하지 않는 것

- 메신저 완료 전에 데스크톱 껍데기를 제품 수준으로 만들기(스파이크는 버리는 코드).
- 데스크톱 전용으로 엔진에 분기 넣기. 차이는 껍데기와 `VisualAdapter` 구현체에만 둔다.
- Live2D·3D 같은 새 외형 형식. 외형 플러그인 층([plugin-architecture.md](plugin-architecture.md))의 일이다.
