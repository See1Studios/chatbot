# 사용자 데이터 분리 · 직책 이름 · 카드 편집 UX · 옛 프로토타입 (계획, 2026-09-24)

상태: **계획**. 실장님 요청(2026-09-24) — 사용량이 부족해 계획만 세워 둔다. 착수는 실장님 말로.

## 1. 사용자에 묶인 데이터 관리 (배포 대비)

**문제**: 개인용으로 시작해 사용자 데이터가 코드 저장소에 섞여 있다. GitHub 원격(`See1Studios/chatbot`)의
`data/workspace/memory/MEMORY.md`에 가족 이름이 이미 올라가 있고, 로컬 커밋에는 자택 위치도 있다(아직 푸시 전).

**원칙**: 저장소 = 엔진(코드·기본 템플릿·기본 역할 팩). 사용자 것은 전부 저장소 밖(또는 git 제외)에 둔다.

| 분류 | 예 | 위치(안) | git |
|---|---|---|---|
| 엔진 | 코드, `templates/`, 기본 `roles/`, 기본 스킬 | 저장소 | 올림 |
| 사용자 설정 | `team.json`, 캐릭터 카드, `visual.md`, 그림, 두뇌 목록 | 사용자 데이터 폴더 | 제외 |
| 사용자 기억 | `memory/MEMORY.md`, 캐릭터 `memory.md`·`private-memory.md` | 사용자 데이터 폴더 | 제외 |
| 런타임 | 세션, 로그, 티켓, 관찰, 잠금, 백업 | 사용자 데이터 폴더 | 제외 |
| 비밀 | `secrets.env`, 토큰 | 사용자 데이터 폴더(권한 600) | 제외 |

단계:
1. 목록 확정: `data/` 아래 모든 경로를 위 표로 분류(표 = SSOT, 테스트로 "분류 안 된 경로 없음").
2. 사용자 데이터 폴더 한 곳(`CHATBOT_DATA`, 기본 `~/.chatbot/`)으로 모으고, 저장소의 `data/`는 비움. 첫 실행은
   템플릿에서 채움(CARD_ONLY_v1의 새 설치 흐름을 그대로 확장).
3. 이 설치의 기존 데이터 이전 스크립트(한 번, 되돌리기 가능).
4. 원격 기록: 이미 올라간 개인정보를 히스토리에서 지울지는 **실장님 결정**(히스토리 재작성·강제 푸시 필요,
   저장소 공개 여부 먼저 확인). 에이전트는 하지 않는다.
5. 가드: 커밋 전 검사(개인정보·비밀 패턴이 추적 파일에 들어오면 실패).

## 2. 직책 이름은 사용자가 정하고, 역할은 지침이 정한다

**문제**: 헌장(`AGENTS.md`) 머리말의 `title: 냥피디`가 직책으로 쓰여 화면에 "냥피디 냥냥"이 뜬다. 이름이 역할을
정하는 것처럼 보이고, 헌장(Tier 3)에 사용자 값이 박혀 있다.

**원칙**: 역할(무엇을 하나)은 역할 팩 지침(`roles/<role>/role.md` 본문)이 정한다. 직책 이름은 표시값일 뿐이며
언제든 바꿀 수 있다.

단계:
1. 헌장 머리말의 `title` 제거(헌장은 사용자 값 없음).
2. 표시 직책 = 캐릭터 카드 `display.title`(사용자 지정) → 없으면 그 캐릭터가 가진 첫 역할 팩의 `title` → 없으면 "Assistant".
3. 코드·지침 어디에서도 직책 이름으로 분기하지 않음(역할 id로만). 기존 NAME_NEUTRAL 테스트에 "직책 문자열 분기 없음" 추가.

## 3. 스키마 있는 데이터는 폼으로 편집

**문제**: 팀 탭이 캐릭터 카드를 JSON 텍스트로 보여 준다. 스키마가 있는 데이터를 텍스트로 고치면 틀리기 쉽다.

대상과 폼:
- 캐릭터 카드(Character Card V2): 이름, 직책(`display.title`), 호칭(`display.user_title`), 말투 한 줄(`display.voice`),
  설명, 성격, 업무 지침(`extensions.chatbot.work.instructions`), 사적 규칙(`system_prompt`) — 긴 글은 textarea,
  나머지는 input. 역할·두뇌는 기존 편집기 재사용.
- `team.json`: 기본 캐릭터 선택 + 역할 칩(기존 `[역할]` 확장).
- 역할 팩 `role.md`: 머리말(title·tools·skills)은 폼, 본문은 textarea.

설계:
- 스키마 SSOT는 서버(`characters.py`에 필드 목록·길이 제한). 페이지는 `GET /api/characters/<id>/form`으로 필드
  정의를 받아 그린다(필드를 페이지에 하드코딩하지 않음).
- 저장은 `PUT /api/characters/<id>` 한 경로, 같은 출처 검사, 서버가 스키마 검증 후 원자적 저장, 이전 판은 `data/backups/`.
- 원문 JSON 보기는 "고급"으로 접어 둠(읽기 전용).
- 테스트: 스키마 밖 필드 거부, 길이 제한, 보호 경로면 읽기 전용, 폼 필드가 서버 정의와 일치.
