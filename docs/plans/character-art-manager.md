# 캐릭터 그림 관리 모달

> 방향 (align/D, 2026-09-29): **핵심** — 캐릭터의 얼굴·표정·장소는 개인화 레이어의 눈에 보이는 절반. 사용자가 직접 넣고 바꿀 수 있어야 "내 친구"가 된다

> 상태: **active** (2026-09-29 초안)
> 목적: 캐릭터 하나의 그림(아이콘·배경·표정)을 한 모달에서 보고, 칸마다 올리기·지우기·생성 요청을 한다. 없는 칸은 무엇으로 대체되는지 보인다.
> 관련: [character-resource-pipeline.md](character-resource-pipeline.md) §10(무대=장소·캐릭터=스프라이트, 이름 대체 사슬, SillyTavern·CCv3 차용) · [character-creation-landing.md](character-creation-landing.md)(소환 마법사의 "모습" 단계가 같은 칸을 씀) · [private-security.md](private-security.md)(업로드 가드)

## 1. 운영자 요청 (2026-09-29)

"캐릭터 이미지 생성 및 관리용 모달이 있으면 좋겠네. 지금은 직접 이미지를 할당할 방법이 없어"

## 2. 현황

- 그림은 캐릭터 폴더의 파일이고, 채팅은 `/api/characters/<id>/avatar|stage|sprites`로 **읽기만** 한다. 올리는 라우트가 없다 — 지금은 에이전트나 사람이 폴더에 파일을 직접 넣는다.
- 형식 검사는 이미 있다: `characters.check_art`(크기·용량·투명). 대체 사슬은 §10 규칙으로 `characters.art_file` 한 곳(구현은 `crp/S2`).
- 올리기 선례: 카드 가져오기(`card_upload.py`), 대화 첨부(`chat_upload.py` — 이름 정리·비밀 이름 거절·용량).

## 3. 선행 사례

| 사례 | 가져올 것 | 버릴 것 |
|---|---|---|

## 4. 설계

### 4.1 모달

- 여는 곳: 캐릭터 트레이의 캐릭터 카드, 팀 탭 캐릭터 카드의 "그림" 버튼. 모달은 그 캐릭터 하나.
- 탭 셋 (CCv3 이름, 화면 말은 한국어): **아이콘**(기본 + 두뇌별 가발), **배경**(`main` + 이름 붙인 장소), **표정**(프레이밍 bust/full 전환).
- 칸 하나 = 이름 하나. 칸은 세 상태를 구분해 보인다: **있음**(그 파일), **대체됨**(흐리게, "→ joy" / "→ neutral" / "→ 기본" 처럼 무엇으로 떨어지는지), **비었음 = placeholder**.
- 표정 탭의 기본 칸: `neutral` + SillyTavern 6개(`sadness` `joy` `love` `anger` `fear` `surprise`), "더 보기"로 28개, "+ 이름"으로 사용자 정의(`joy.giggle`처럼 접미사).
- 칸 동작: **올리기**(클릭·끌어다 놓기·붙여넣기) · **지우기**(확인) · **생성 요청**(4.3). 여러 장 표정은 칸 안에 작은 표시.
- 모달 위쪽: "ZIP 팩 가져오기"(SillyTavern 스프라이트 팩, 평평한 이름 그대로), 형식 경고(`check_art` 결과 한 줄씩).

### 4.2 서버 (`character_art.py`에 쓰기 라우트)

- `POST /api/characters/<id>/art?kind=&name=&framing=&brain=` 본문 = 그림. `DELETE` 같은 주소.
- 받으면: 종류·이름은 슬러그만, 이미지 형식은 내용으로 판별(PNG·WebP·JPEG), 용량 상한 → Pillow로 규격 크기에 맞춰 WebP로 저장, 원본은 같은 이름 `.png` 마스터로(운영자 결정 Q1과 함께). 표정은 투명 필수, 배경은 투명 금지 아님.
- 저장 위치는 §10 이름 규칙 그대로. 저장 뒤 `check_art` 결과와 새 `v`(캐시 무효화)를 돌려준다.
- 가드: 사적 세션에서는 이 라우트를 부르지 않는다(모달은 업무·팀 화면). 카드 정본·잠긴 마스터는 덮지 않는다(§2.1 정본 규칙).

### 4.3 생성 요청

- 칸의 "생성"은 그림을 직접 만들지 않는다. **작업 티켓**을 만든다: `character-art` 스킬, 그 캐릭터, 빠진 이름 목록, §10 사양(배경은 인물 금지, 표정은 투명·같은 캔버스·같은 기준점).
- 사적 모드에서는 위임이 막혀 있으니(업무 경계) 모달은 업무 쪽에서만 생성 버튼을 보인다.
- 완료되면 모달이 새로 읽는다. 어느 이미지 모델을 쓸지는 에이전트 쪽 결정(키 없는 경로 우선).

### 4.4 갤러리 = 후보함, 위임 그림과 이어짐 (2026-09-29 운영자)

운영자: "코코가 위임해서 그림을 한 장 그려왔어. 그런데 정작 아티팩트 등 어디에서도 열람할 방법이 없네. 이미지 파이프라인과 자연스럽게 통합". 위임 에이전트의 그림은 `characters/<id>/gallery/`에 떨어진다(파이프라인 §2.1 "후보만 gallery에"). 모달의 첫 탭이 갤러리이고, 갤러리 그림을 칸에 넣는 것이 운영자의 승인이다. 갤러리에 쓴 작업이 끝나면 작업 카드에 [갤러리] 버튼이 생겨 그 캐릭터의 모달로 바로 연다. 칸에서 치운 그림은 갤러리로 돌아간다(삭제 없음).
