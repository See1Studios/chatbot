# 캐릭터 이벤트 우편 · 단체방 · 예약

> 방향 (align/D, 2026-09-30): **핵심** — 캐릭터가 "내 일·내 주변에 무슨 일이 있었는지" 알고 먼저 반응하고, 여럿이 모여 떠드는 것은 개인화 레이어가 살아 있다고 느끼게 하는 부분이다

> 상태: **active** (2026-09-30 초안)
> 목적: 작업·시스템·대화 이벤트를 한 곳에 모아 **관계있는 캐릭터에게 배달**하고(조용히 또는 자동 반응으로), 같은 바탕 위에 **여러 캐릭터가 모이는 단체방**(멘션 포함)을 올린다.

## 1. 운영자 제안 (2026-09-30)

- "작업 관련 이벤트나 시스템 관련 이벤트가 관계가 있는 캐릭터한테 자동으로 배송되고 배송(연락)받은 캐릭터가 자동으로 반응하는 그런 시퀀스도 좋을 것 같아. 중앙 메시지 이벤트시스템이 있어서 각 이벤트들을 수집하고 수취인한테 배송하는 그런 시스템 어때? 사적 대화 시작/끝도 그런 이벤트 중 하나가 되고."

- "이걸 확장해서 간이 크론? 같은 걸 만들수도 있겠지?"

## 2. 현재 사실 (2026-09-30)

같은 일("무슨 일이 생겼다 → 누군가에게 알린다")을 제각각 한다.

| 있는 것 | 하는 일 | 한계 |
|---|---|---|
| `server._boot_notice` (턴 훅 `session.boot_notice`) | 재시작 뒤 첫 턴에 "재기동됨, 반영: …" 한 줄 | 재시작 한 종류만 |
| `delegation.work_note` (WORK_NOTE_v1, #465·#466) | 위임 작업 단계가 바뀌면 작업자·기본 캐릭터의 다음 턴에 한 줄 | 위임 한 종류만, 사용자가 말을 걸어야 전달 |
| private-mode §8 장면 지문 | 방을 바꾸면 캐릭터가 먼저 반응하도록 지문 한 줄 | 사적 모드 안에서만 |
| `obslog` `logs/events.jsonl` | 엔진 사건 기록(진단용) | 배달 개념 없음, 본문 규칙이 다름 |
| `ux/B` (계획) | 화면으로 나가는 캐릭터 상태(`emotion`·`speaking`·`presence`) | 캐릭터에게 들어가는 쪽은 없음 |
| 세션 | 캐릭터 × 모드(업무/사적)마다 하나 | 여러 캐릭터가 한 대화에 모이는 자리 없음 |
| 단체방 화면 (`static/app-rooms.js`, #475) | 캐릭터 트레이 버튼 → **팝업 모달** 안에 방 목록·대화·입력창 | 1:1 대화와 따로 논다: 말풍선·입력창·키보드 처리를 모달이 따로 갖고, 모달을 닫으면 방이 화면에서 사라진다 (→ 4.8, 결정 E9) |

지침 묶음은 CLI 두뇌에 첫 턴에만 들어가므로(#465 원인), 대화 도중 생긴 일은 **턴 앞 한 줄**이나 **캐릭터가 먼저 거는 말**로만 전할 수 있다.

## 4. 설계

### 4.1 이벤트

`{id, ts, type, subject, payload, audience}` 한 줄. 본문(대화 내용)은 싣지 않는다 — 필요한 것은 id로 가리킨다.

| 종류(예) | subject | payload |
|---|---|---|
| `work.phase` | 티켓 | 제목, 단계, 작업자 캐릭터, 태스크 n/m |
| `host.restart` | — | 시각, 반영 커밋 |
| `host.incident` | 사건 id | 코드, 심각도 — 끌 수 없음, 기본 캐릭터에게만(improvement-layers il/E) |
| `account.switch` | 제공자 | (메일 없이) 바뀜 여부 |
| `session.private.start` / `.end` | 캐릭터 | 시각만 |
| `room.message` | 방 | 말한 쪽, 멘션 목록, 메시지 id |
| `room.private.start` / `.end` | 방(단체 놀이방) | 시각만 |
| `time.schedule` | 예약 | 예약 이름, 수취인, 짧은 메모 |
| `user.presence` | — | 돌아옴/자리 비움(화면 신호) |

### 4.2 우편국

- 이벤트는 데이터 폴더의 추가 전용 기록 한 곳에 쌓고(`<DATA>/events/`), 캐릭터마다 **어디까지 받았는지(커서)**를 둔다. 재시작해도 이어진다.
- 발행은 한 함수(`events.publish`), 엔진 코드는 수신자를 모른다.
- `work_note`·`_boot_notice`는 **1단계에서 이 위로 옮긴다**(문구 표는 그대로).

### 4.3 수취인 규칙 — 관계로, 이름 없이

규칙은 데이터(`<workspace>/events.json`, 없으면 기본값). 엔진은 **자리·관계**만 안다(engine/A #460 원칙):

| 관계 | 뜻 |
|---|---|
| `worker` | 그 작업의 현재 태스크를 하는 캐릭터 |
| `default` | 기본 캐릭터(위임하고 확인하는 쪽) |
| `self` | 그 세션·방의 주인 캐릭터 |
| `participants` | 그 일이 일어난 자리에 있던 캐릭터 — 1:1이면 그 캐릭터, 방이면 방 멤버 |
| `members` | 방의 구성원 |
| `mentioned` | 멘션된 캐릭터 |
| `all` | 모든 캐릭터 |

### 4.4 배달 두 가지

- **조용한 배달**: 다음에 사용자가 그 캐릭터에게 말을 걸 때 턴 앞 한 줄(지금 `work_note` 방식). 비용 거의 0.
- **자동 반응**: 배달되면 캐릭터가 **먼저 한마디** 한다(그 캐릭터 세션에 캐릭터 말풍선). 두뇌 호출이라 구독 한도를 쓴다. 안전장치(기본값은 결정 E2):
  - 이벤트 종류별 켜기/끄기, 캐릭터별 끄기
  - 빈도 제한(캐릭터당 시간당 N회), 방해 금지 시간
  - 사용자가 다른 대화 중이면 미루고 모아서
  - 사적 세션 안에서는 업무 이벤트로 먼저 말하지 않음

### 4.5 사적 이벤트 (private-security T1·T3)

- 사적 이벤트는 **내용 없이 시각만**. 알림·미리보기에도 본문 없음(T1).
- 기본 수취인은 **그 자리의 참여자(`participants`)와 화면(`ux/B` presence)** 뿐 — 1:1 사적 대화면 그 캐릭터, **단체 놀이방이면 방 멤버**. 자리에 없던 캐릭터·업무 쪽에는 가지 않는다(T3). (운영자 2026-09-30: "단체방에서는 단체방에 있는 멤버들만 대상이 되면 되지 않을까")
- 다른 캐릭터가 알게 하는 것(질투·눈치 연출)은 캐릭터별로 켜는 선택 기능 — 결정 E1.

### 4.6 단체방

- **방** = 구성원을 가진 주제. 방 기록은 방 하나에 쌓이고, 각 캐릭터는 자기 차례에 **방의 최근 대화 + 자기 카드·역할·업무 기억**으로 말한다. **사적 기억은 단체방에 넣지 않는다**(사적 이야기가 나오면 "나중에 둘이" 쪽으로).
- **멘션**: 입력창 `@` → 구성원 자동완성, 멘션된 캐릭터가 먼저 말한다. 캐릭터가 다른 캐릭터를 멘션할 수도 있다(턴 한도 안에서).
- **발언자 선택**: SillyTavern 방식 이름을 따른다 — `natural`(멘션 우선 → talkativeness 확률), `list`(순서대로), `manual`(사용자가 고름). 기본은 결정 E4.
- **끝없는 대화 막기**: 사용자 한마디당 최대 K번 캐릭터 발언, 캐릭터끼리 이어 말하기 최대 J번, 그다음은 사용자 차례. 비용 표시(이번 턴에 두뇌 몇 번).
- 두뇌는 캐릭터마다 자기 것(두뇌 목록·예비 두뇌 그대로), 제공자 중립.
- **방의 모드**: 업무방과 **단체 놀이방(사적)**. 놀이방은 사적 모드 규칙(업무 기억·위임 닫힘, 사적 이벤트는 멤버에게만)을 따르고, 기억은 **방 자신의 사적 기억**을 쓴다. 캐릭터마다의 1:1 사적 기억은 다른 멤버가 듣게 되므로 넣지 않는다(결정 E7).

### 4.7 예약 — 간이 크론

- 시계도 이벤트 발행자 하나다. 예약이 때가 되면 `time.schedule`을 올리고, 우편국이 수취인에게 배달한다(조용히 또는 자동 반응). 아침 인사, 리마인더("약 먹을 시간"), 정기 점검.
- 예약: `{id, 이름, 수취인(캐릭터·관계), 때(매일 HH:MM · 요일 · 간격 · 한 번: 시각/N분 뒤), 메모, 켜짐}` — 데이터 파일 한 곳, 화면은 "매일 08:00" 같은 말로(크론 문법 노출 안 함).
- 놓친 예약(서버가 꺼져 있던 동안)은 켜질 때 **한 번만** 배달하고 쌓아 두지 않는다.
- 캐릭터가 "30분 뒤에 알려줘"를 받아 도구로 예약을 만들 수 있게 할지는 결정 E8. 만들면 화면에 보이고, 사용자가 지울 수 있다.
- 방해 금지·빈도 제한은 자동 반응(4.4)의 것을 그대로.

### 4.8 단체방을 메인 대화창으로 (결정 E9)

방은 1:1 캐릭터와 **같은 급의 대화 상대**다. 방을 고르면 팝업이 뜨는 대신 메인 대화창(`#log`)과 메인 입력창(`#input`)이 그 방으로 바뀐다.

- **고르기**: 캐릭터 트레이에 캐릭터와 방이 함께 나온다. 지금 상대가 캐릭터인지 방인지는 화면 머리(이름·멤버 수)로 보인다. 새로고침해도 마지막 상대(캐릭터 또는 방)로 돌아온다.
- **대화창**: 방 메시지는 메인 말풍선 그대로(아바타·화자 이름·같은 화자 연속 묶기·마크다운). 방 전용 말풍선(`.room-msg` 등)은 없앤다. 상대를 바꾸면 대화창을 통째로 갈아 끼운다 — 1:1 기록과 방 기록은 섞이지 않는다.
- **입력창**: 메인 입력창 하나. 상대가 방이면 전송은 방 API(`/api/rooms/<id>/say`)로 가고 `@` 자동완성이 켜진다. 방이 답하는 동안 전송 버튼을 잡아 두는 것(#476)과 모바일 키보드 처리는 메인 것을 그대로 쓴다.
- **방에서 안 되는 위젯**: 서버의 방이 받지 않는 것(모델 고르기·사적 전환·첨부 등)은 방에서 숨긴다. 방이 받게 되면 그때 켠다 — 화면이 먼저 약속하지 않는다.
- **모달로 남는 것**: 새 방 만들기·멤버 고치기 같은 짧은 양식만. 대화는 모달에 두지 않는다.
- **그대로 두는 것**: 서버(`room_chat.py`, `/api/rooms`)와 방 기록 형식, 발언자 선택·턴 한도(E4), 방 메시지 폴링. E5 비용 표시는 메인 입력창 옆에 붙는다(놀이방과 함께 별도 항목).
