## 3. 범위 / 비목표

**범위**
1. 층 목록 하나(층 id, 정적/동적/턴별, 어느 모드에서, 출처, 크기 상한)를 만들고 번들을 그 목록으로 조립. **결과 텍스트는 지금과 바이트 단위로 같아야 한다.**
2. 동적 층이 바뀌면 바뀐 층만 짧게 다시 알린다.
3. 로어북을 턴별 층으로: 걸린 항목이 바뀔 때만 그 부분을 알린다.
4. 주입 기록: 턴마다 무엇을 왜 넣었는지 한 줄 이벤트. 상태 탭에서 세션별로 본다. 크기·누락 경보.

**비목표**
- 장소·장면에 따른 층 교체: 장면 신호가 아직 없다. 생기면 층 하나를 더하는 일로 끝나게 구조만 열어 둔다.
- 글 품질(Anti-Slop)·Oxlint: 별도 계획.
- 프로바이더별 분기: 모든 프로바이더가 같은 번들을 받는다(지금처럼).

## 5. 구조

```text
층 목록 (LAYERS)       종류     모드             출처
  charter              정적     업무·사적*       AGENTS.md (*사적은 앞부분 + Scope)
  persona              정적     업무·사적        카드 (+ 업무 지시 / 사적 규칙)
  roles                정적     업무             역할 팩
  skills               정적     업무             스킬 색인 (역할로 거름)
  lore                 턴별     업무·사적        로어북 (최근 대화로 매칭)          ← D-3
  house_memory         동적     업무             MEMORY.md
  own_memory           동적     업무             캐릭터 기억
  private_memory       동적     사적             사적 기억 + 관계 기억
  names                동적     업무·사적        이름 변경
  status               동적     업무             자기개선 상태

조립:  모드에 맞는 층만 → 정적 해시(지금과 같음) + 동적 해시(층별) + 턴별(로어북)
주입:  첫 턴/정적 변경 → 전체 · 동적 층 변경 → 그 층만 [갱신] · 로어북 변경 → 그 부분만
기록:  context.inject {sid, provider, mode, character, why, hash, chars, layers:[{id, kind, chars, hash}]}
```

## 7. 순서 · 리스크

**순서**: A(동작 그대로 정리) → B(기록) → F(경보) → C·D(동작 변경) → E(화면) → G(실측). 기록이 먼저 있어야 C·D가 바꾼 것을 숫자로 본다.

**리스크**
- 정리하다 번들이 한 글자라도 바뀌면 모든 세션이 재주입된다 → lca/A의 바이트 동일 테스트가 막는다.
- `[갱신]` 블록이 잦으면 토큰이 는다 → 층별 상한과 "바뀐 층만" 규칙, lca/B 기록으로 실측.
- 로어북 매칭이 턴마다 돌면 느려질 수 있다 → 최근 대화 깊이 상한(지금 5), 걸린 묶음이 같으면 아무것도 안 붙임.
- 사적 모드에 업무 층이 새는 것 → 목록의 모드 칸 + lca/F 테스트.
