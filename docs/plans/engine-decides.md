## 1. 원칙과 판정 기준

한 지점을 엔진으로 옮길지는 세 질문으로 정한다.

1. **엔진이 이미 아는가?** (상태·세션·역할·경로·쿨다운) → 아는 것은 엔진이 정한다. 모델에게 묻지 않는다.
2. **모양으로 판정되는가?** (`*…*`는 행동, `(…)` 전체는 행동) → 모양 규칙 하나를 엔진과 화면이 함께 쓴다(`dialog_log.pieces`, `static/app-blocks.js::blockIsStaged`).
3. **창작인가?** (대사, 행동, 선택지의 문구, 계획을 작업으로 나누기) → 모델에 남긴다. 대신 형식은 엔진이 관대하게 받는다.
4. **지침에 한 줄 더하면 풀리는가?** → 먼저 엔진이 관대하게 받는 쪽을 고른다. 지침 한 줄은 매 턴, 모든 모델, 모든 캐릭터가 내는 비용이고 그래도 틀린다 (운영자 2026-10-03: "명확한 기능을 에이전트 판단에 기대지 않고 명확하게 로직 루틴을 타게 하면서 매턴 소비되는 토큰 양도 신경써줘"). 관대함에는 경계를 둔다: 아는 키만, 모양이 정확히 맞을 때만, 모르는 것은 무시 ("유연해지는 건 구멍도 크다", 같은 날).

판단이 꼭 필요하지만 창작이 아닌 것(분류 등)은 **두뇌와 무관한 고정 판정기**로 옮긴다: 규칙 → 그래도 안 되면 고정된 값싼 모델 한 번(`session._oneshot`, `CHATBOT_ONESHOT_PROVIDER`). 대화 두뇌가 바뀌어도 판정은 같다.

이미 엔진이 정하는 선례(재사용 대상):

| 장치 | 무엇을 엔진이 정하나 |
|---|---|
| `dialog_log.pieces`, STAGE_v1 (`static/app-blocks.js`) | 말/행동 구분 — 모양으로 |
| `dialog_tool.ALIASES`, `turn_note` (#565·#567) | 인자 이름 보정, 받은 글은 엔진이 넣고 읽음 처리 |
| `private_engine.tension_step` | 텐션 단계 — 고른 선택지의 칸 번호로 |
| `items.py` + `engine_data/affection.json` (private-mode D8) | 아이템 판정·호감도 — 모델 아님 |
| `room_chat.pick` | 단체방에서 누가 말할지 |
| `event_react` | 캐릭터가 언제 먼저 말할지 |

## 7. D6 설계 — 개발판 대화 에이전트는 worktree에서 (2026-10-08)

- **문제**: 대화 에이전트(agy 등)는 자체 셸로 main 작업 폴더를 바로 고친다. 재시작은 그 폴더를 그대로 읽고, 다른 에이전트·러너도 같은 폴더를 쓴다. A5 훅은 착륙·작성자 실수만 막는다.
- **설계**: 개발판에서 대화 세션이 티켓을 잡으면(`ticket` 도구의 claim/start) 엔진이 그 티켓의 worktree(`~/.worktrees/chatbot/ticket-<id>`, 브랜치 `worktree/ticket-<id>`)를 만들고, 도구 결과와 다음 턴 안내에 그 경로를 한 줄로 준다. 고치고 테스트하고 커밋하는 곳은 거기다.
- **감시**: `write_guard`의 작업 폴더 비교(TREE_WATCH_v1)가 대화 세션의 턴 동안 main 작업 폴더에 생긴 변경을 찾으면, 지금의 "보류" 대신 턴을 멈추고 worktree에서 다시 하라고 알린다.
- **착륙**: 대화 세션의 `done`은 바로 닫지 않고 병합 대기(`awaiting_merge`)로 넘긴다. 운영자 [승인]이 러너와 같은 경로(게이트 → ff 병합)로 착륙시킨다.
- **한계**: 같은 사용자 권한이라 일부러 피하는 것은 못 막는다. 실수와 관성을 막는다.
- **항목**: `ed/E1` worktree 만들기와 안내 · `ed/E2` main 쓰기 감지 시 턴 멈춤 · `ed/E3` `done` → 병합 대기 연결. 각각 테스트.
- **버튼(B7과 함께)**: ed/E3는 이 티켓 종류를 `delegation.WORK_ACTIONS` 표에 줄로 더한다(화면은 손대지 않음). 지금 그 `awaiting_merge`에는 러너 상태 파일이 없어 `merge()`가 거절하므로, 상태 파일을 만들거나 `merge()`가 그 종류를 알아야 한다.

## 6. 이 계획이 하지 않는 것

- 캐릭터의 말·행동·선택지 문구·계획 나누기를 엔진이 쓰지 않는다.
- 호스트 공지를 모델 기록의 system 역할로 넣지 않는다. 공지는 화면 이벤트다.
- 보안 경계(허용 루트, 명령 허용 목록, Tier 3 거절, 운영자 몫 동작)를 넓히지 않는다. 정규화는 이름과 모양만 고친다.
- 제공자별 분기를 공통 코드에 넣지 않는다(agy 포장 풀기도 모양으로 판정).
