## 1. 원칙과 판정 기준

한 지점을 엔진으로 옮길지는 세 질문으로 정한다.

1. **엔진이 이미 아는가?** (상태·세션·역할·경로·쿨다운) → 아는 것은 엔진이 정한다. 모델에게 묻지 않는다.
2. **모양으로 판정되는가?** (`*…*`는 행동, `(…)` 전체는 행동) → 모양 규칙 하나를 엔진과 화면이 함께 쓴다(`dialog_log.pieces`, `static/app-blocks.js::blockIsStaged`).
3. **창작인가?** (대사, 행동, 선택지의 문구, 계획을 작업으로 나누기) → 모델에 남긴다. 대신 형식은 엔진이 관대하게 받는다.

판단이 꼭 필요하지만 창작이 아닌 것(분류 등)은 **두뇌와 무관한 고정 판정기**로 옮긴다: 규칙 → 그래도 안 되면 고정된 값싼 모델 한 번(`session._oneshot`, `CHATBOT_ONESHOT_PROVIDER`). 대화 두뇌가 바뀌어도 판정은 같다.

이미 엔진이 정하는 선례(재사용 대상):

| 장치 | 무엇을 엔진이 정하나 |
|---|---|
| `dialog_log.pieces`, STAGE_v1 (`static/app-blocks.js`) | 말/행동 구분 — 모양으로 |
| `dialog_tool.ALIASES`, `turn_note` (#565·#567) | 인자 이름 보정, 받은 글은 엔진이 넣고 읽음 처리 |
| `private_engine.tension_step` | 텐션 단계 — 고른 선택지의 칸 번호로 |
| `items.py` + `engine_data/affection.json` (private-mode D8) | 아이템 판정·호감도 — 모델 아님 |
| `room_chat.pick` | 단체방에서 누가 말할지 |
| `event_react` | 캐릭터가 언제 먼저 말할지 |
| `adapter_base.split_choices`, `rescue_leaked_choices` | 선택지를 본문에서 떼어 냄, 새어 나온 도구 호출 구조 |
| `mcp_caller` (inbox/0) | 도구를 부른 세션 — 모델 인자가 아니라 프로세스 족보로 |

### A. 도구 인자 형식

**ed/A1 인자 정규화 층 (모든 도구 공통)** — P1 · S–M
- 지금: 도구마다 따로 검사. 보정은 `dialog_tool.ALIASES` 하나뿐.
- 틀리면: 같은 호출을 2–4번 다시 함(토큰·시간), 포기하면 할 일이 안 됨.
- 흔적: 위 표에서 동작 이름·키 이름·포장·문자열 배열이 약 75건.
- 엔진: `mcp_server.call_tool` 앞에 한 층. ① agy 포장 풀기 ② 키 소문자화 ③ 문자열로 온 배열·객체 파싱(`tasks`, `paths`) ④ 도구별 별칭표(`dialog_tool.ALIASES`를 일반화: `command`→`cmd`, `query`→`pattern`, `content`→`body`) ⑤ 동작 동의어(`show`→`get`, `status`→`list`, wiki `read`→`get`) ⑥ 동작 추론(`memory`에 `fact`만 → `add`, `query`만 → `search`; `observation`에 제목·본문 → `add`). 운영자 몫 동작(`approve`, 실행·착륙)은 동의어로 바꾸지 않고 지금처럼 거절.
- 남길 것: 무엇을 부를지는 모델. 별칭표는 provider 이름 없이(`test_provider_neutrality`).
- 완료 기준: `mcp.call` 실패율 19% → 10% 아래(같은 기간 길이로 비교).

**ed/A2 경로 해석** — P2 · S
- 지금: 허용 루트 밖이면 거절.

### B. 도구를 부를지 말지

**ed/B1 애정 턴 표시 (`personal_turn`)** — P1 · M · 결정 D1
- 지금: 업무 세션에서 사용자 말이 사적이면 모델이 답하기 전에 도구를 부름(charter "Personal moments"). 표시되면 업무 도구가 닫히고 기억·관찰·회상에서 빠짐.
- 틀리면: 놓치면 애정 대화가 업무 기억·관찰 후보·`recall_memory`로 들어감(사생활 누수, 되돌리기 어려움). 잘못 표시하면 일하는 중 업무 도구가 닫힘. 두뇌마다 민감도가 다름 — 원칙이 겨누는 바로 그 차이.
- 흔적: 호출 67건, 실패 0. 놓친 수는 본문 없이는 모름(D5).
- 엔진: 턴 시작 때 엔진이 판정해 표시. 순서: ① 사용자의 명시 신호(입력창 ♥ 토글, 업무방의 `/act`) ② 고정 판정기 — 값싼 고정 모델 한 번(`_oneshot`, 사용자 말 한 줄만, 결과는 personal/work 한 단어), 턴과 나란히 돌리고 도구 호출 전에 결과를 기다림(상한 2초, 넘으면 work). 도구는 전환 기간에 "덮어쓰기"로만 남기고, 측정 뒤 지침에서 뺌.
- 함께 고칠 것: `mcp_server._live_scope`가 **턴을 돌리는 세션 전부**를 보고 닫음 → 다른 창의 사적 대화나 애정 턴이 이 창의 업무 도구까지 닫음. 부른 세션(`mcp_caller`)만 보게.
- 남길 것: 표시된 턴에서 어떻게 반응할지(살짝 당황, 짧게, 일로 돌아가기)는 캐릭터 연기라 모델.

**ed/B2 사적 대화 이동 제안** — P1 · S–M · 결정 D3
- 지금: `personal_turn` 결과가 "답 끝에 이동 선택지를 붙여라"라고 말하면, 모델이 장소를 지어내고 `/private on <장소>` 명령 형식까지 써야 함. 쿨다운(`offers_left`)은 엔진이 셈.
- 틀리면: 선택지가 빠지거나, `command:` 형식이 틀려 누르면 라벨이 말로 나감, 쿨다운을 무시하고 또 제안.
- 흔적: 도구 쪽 실패는 없음. 형식 오류는 답변 본문에 있어 미측정.
- 엔진: 표시 + `offers_left`이면 엔진이 그 턴의 선택지에 이동 칩 두 개를 직접 붙임(`split_choices` 뒤, 모델 선택지와 합침): "잠깐 <장소>…" → `/private on <장소>`, "일 계속하기". 장소는 엔진이 고름(D3). 모델은 반응만.
- 남길 것: 없음(문구 톤은 장소 목록이 담당).

**ed/B3 선택지 (`choices`)** — P2 · M · 결정 D2·D4
- 지금: 채널이 둘 — 도구 `choices`와 본문 끝 `<!--choices: …-->`. 모델이 언제 낼지, 어느 채널로, 어떤 형식으로 낼지 정함. 도구 호출이 글로 새는 사고가 있어 구조 장치가 있음(CHOICES_LEAK_RESCUE_v1). 사적 방은 매 답변 필수, 형식 `라벨 -> (행동)`.
- 틀리면: 사적 방에서 선택지가 없으면 다음 수를 고를 수 없음(4.5%). 형식이 틀리면 칩이 말로 나가거나 텐션 칸이 안 잡힘.
- 흔적: 도구 13건(실패 1), 업무 `choices` 이벤트 591, 사적 누락 56/1,235.
- 엔진: ① 지침은 채널 하나만 가르침(D2). 엔진은 둘 다 계속 받음. ② 사적 방 형식은 관대하게: 괄호 없는 오른쪽은 행동으로 감쌈(모든 사적 칩은 어차피 `/act`). ③ 사적 방에서 선택지가 없으면 엔진 대체(D4): 텐션 표(`engine_data/private_tension_*.json`)의 칸별 기본 행동으로 2–3개.
- 남길 것: 선택지의 **문구**와 업무방에서 **낼지 말지**는 대화 판단이라 모델.

**ed/B4 위임 (`delegate`)** — P2 · M
- 지금: 누가 위임할 수 있는지는 역할 팩의 `tools`로 엔진이 정함(TEAM_ROLES_v2, 권한 없는 캐릭터는 거절). 직접 할지 위임할지는 `roles/lead/PROCEDURE.md`의 예외 목록을 모델이 읽고 정함. 남은 판단은 계획 모양: 역할 고르기, 제목, 어떤 티켓을 다시 계획할지, 경로 등급.
- 흔적: 대기 아닌 티켓 재계획 17, 운영자 몫 동작 13, 문자열 `tasks` 7(→A1), 없는 역할 1, 제목 없음 3, Tier 3 3.
- 엔진: ① 역할이 없거나 틀리면 경로로 정함(그림 경로 → `art`, `docs/plans/` → `plan`, 그 외 코드 → `dev`; 표는 역할 팩 메타에) ② 제목 없으면 첫 작업 제목 ③ 대기 중이 아닌 티켓을 다시 계획하면 새 계획으로 받고 옛 티켓을 링크(거절 대신) ④ 거절 문구에 지금 그 티켓으로 할 수 있는 것 한 줄.
- 남길 것: 일을 작업으로 나누고 지시문을 쓰는 것은 PD의 일이라 모델.

**ed/B5 "기억해"** — P3 · S
- 지금: 모델이 알아채고 `memory add`.
- 엔진: 사용자 말에 기억 요청어(`engine_data` 목록, i18n 카탈로그)가 있으면 턴 안내 한 줄(`[Engine] The user asked you to remember something: call memory add`) + 턴 끝에 호출이 없었으면 `memory.missed` 로그. 사실을 한 줄로 뽑는 일은 모델.

**ed/B6 승인 먼저 (큰 작업 전 묻기)** — 남김
- 범위가 큰지는 요청의 의미 판단. 엔진 몫은 이미 있는 비용 상한(웹 도구 제한, 관찰 개수 상한)으로 충분. 계획에서 바꾸지 않음.
