# 단체방 대화창 상단 헤더 개편 및 단체방 정보 서랍 (group-room-header)

> 방향 (align/D, 2026-10-02): **핵심** — 단체방 헤더에 카드 스택 아바타 연출 및 실시간 기척 동기화를 적용하고, 헤더 인터랙션으로 단체방 정보 서랍(Room Drawer/Panel)을 열어 1:1 대화방과의 시각적·기능적 UX 일관성을 완성하는 개선 계획
> 상태: **active** (2026-10-02 수립)
> 관련: [character-events-and-rooms.md](character-events-and-rooms.md) · [ux-shell-roadmap.md](ux-shell-roadmap.md) · [ARCHITECTURE.md](../ARCHITECTURE.md)

## 1. 배경 및 문제 의식

메신저 셸 2.0([ux-shell-roadmap.md](ux-shell-roadmap.md) `ux/S1`~`ux/S7`, `html.shell2`) 도입 이후, 1:1 대화방은 현대적인 메신저 디자인 언어로 개편되었습니다.  
헤더에는 캐릭터 아바타, 이름, 현재 장소 및 기척(`shellPresence`)이 유기적으로 표시되며, 헤더(아바타/이름)를 누르면 우측에서 프로필 카드(`shellProfile`)가 매끄럽게 슬라이드되어 열립니다.

그러나 단체방([character-events-and-rooms.md](character-events-and-rooms.md) `evt/E-3`)은 메인 대화창에 통합되었음에도 불구하고, 상단 헤더 영역이 여전히 초기 프로토타입 수준의 텍스트 덧붙임(`roomHead`) 구조에 머물러 있습니다.

### 현재 단체방 헤더의 4대 결함

1. **아바타 동기화 및 연출 부재**:
   - 좌측 대화목록(Shell List)에는 최근 발화자 얼굴과 겹친 카드 스택 효과(`#520`, `.shell-row.is-room`)가 적용되었으나, 정작 메인 헤더(`#brandAvatar`)는 단체방에 들어가도 이전 1:1 캐릭터의 얼굴이 그대로 남아있거나 방 전용 연출이 없습니다.
2. **헤더 인터랙션 무반응 (죽은 헤더)**:
   - 1:1에서는 헤더를 클릭하면 프로필 카드가 열려 캐릭터 정보와 두뇌를 제어할 수 있지만, 단체방에서는 `roomOpenId()` 검사로 인해 헤더 클릭이 완전히 차단되어 아무 일도 일어나지 않습니다.
3. **기척(Presence) 및 턴 상태 미연동**:
   - 단체방 진행 중 특정 캐릭터가 답변을 작성하고 있을 때(방 상태 `busy`), 헤더 서브타이틀은 여전히 "3명 · 노노, 유키, 코치" 텍스트만 고정되어 있으며, "노노 작성 중…" 같은 실시간 기척 애니메이션이 연동되지 않습니다.
4. **단체방 관리 및 멤버 탐색 경로의 부재**:
   - 단체방의 전체 멤버 확인, 발언 모드(`natural` 자연 / `list` 순차 / `manual` 수동) 전환, 멤버 추가(초대), 방 이름 변경, 방 나가기/삭제를 수행할 수 있는 직관적인 헤더 서랍(Room Drawer/Card) 인터페이스가 없습니다.

## 2. 목표 및 핵심 원칙

1. **디자인 언어 일관성 (Visual Parity)**:
   - 단체방 상단 헤더를 메신저 셸의 Shell2 규격 및 Impeccable 디자인 시스템과 100% 일치시킵니다.
2. **카드 스택 아바타 연동 (Dynamic Card-Stack Avatar)**:
   - 단체방 헤더 아바타에 좌측 대화목록과 동일한 **카드 스택(Card Stack) 연출**을 적용합니다.
   - 최근 발언한 캐릭터의 얼굴을 최상단에 표시하며, 발언 기록이 없으면 방 첫 번째 멤버 또는 단체방 기본 이니셜을 표시합니다.
3. **실시간 기척 동기화 (Live Turn Presence)**:
   - 평상시에는 "N명 · 멤버 요약"을 표시하고, 단체방 턴 진행 중(Busy)에는 1:1과 동일하게 **"○○ 작성 중… + 펄스 점(busy dot)"**으로 부드럽게 전환합니다.
4. **단체방 정보 서랍 (Room Profile / Drawer)**:
   - 단체방 헤더를 클릭하면 우측 슬라이드 패널(모바일은 시트)로 단체방 정보 서랍을 엽니다.
   - 방 정보(아바타, 이름, 생성일), 참여 멤버 목록 및 1:1 바로가기, 발언 순서 제어, 멤버 초대, 방 나가기/삭제 액션을 완결된 형태로 제공합니다.
5. **엄격한 크기 상한 준수 (Guard & Budget)**:
   - `static/app-shell.js`는 현재 약 41.9KB로 상한선인 43KB에 매우 근접해 있습니다 (`test_page_scripts.py`).
   - 단체방 서랍 및 헤더 로직은 약 20KB로 여유가 충분한 `static/app-rooms.js`에 격리 구현하고, `app-shell.js`에서는 최소한의 훅과 인터페이스만 위임받아 파일 상한 가드를 완벽히 보호합니다.

## 3. 세부 설계

### 3.1 상단 헤더 구조 (Header Architecture)

```
[ ← 뒤로가기 ]  [ 카드스택 아바타 ]  [ 방 이름 ▾ ]
                                    [ 3명 · 노노, 유키, 코치 ] / [ ✦ 노노 작성 중… ]
```

- **아바타 영역 (`#brandAvatarWrap`)**:
  - 단체방 진입 시 `.is-room` 클래스 부여.
  - 뒤쪽에 2중 레이어 카드 그림자/스택 프레임(`.room-avatar-stack`) 렌더링.
  - 최신 발언 캐릭터의 아바타 이미지로 자동 갱신 (`characterOwnPortrait` / `/api/characters/<id>/avatar`).
- **타이틀 영역 (`#brandName` & `#roomHead`)**:
  - 방 이름 말줄임표(`text-overflow: ellipsis`) 처리 및 전체 이름 호버 툴팁.
  - 클릭 가능한 버튼 역할(인터랙션 힌트 및 커서 포인터 유지).
- **서브타이틀 영역 (`#brandRole` / `.room-head-sub`)**:
  - **대기 상태**: `N명 · [멤버1, 멤버2, ...]` (한글/영문 로케일 호환, `roomMembersLabel`).
  - **발화 진행 상태**: `roomState.busy` 및 `roomState.speaking` 감지 시 즉시 `[캐릭터명] 작성 중…` 기척 애니메이션 활성화 (기존 `shellPresenceText` / `.busy` 스타일 공유).

### 3.2 단체방 정보 서랍 (Room Profile / Drawer)

우측 프로필 슬라이더(`#shellProfile`) 프레임워크를 공유하여 일관된 경험을 제공합니다.

1. **상단 프로필 헤더**:
   - 대형 카드 스택 아바타 (80px~96px).
   - 방 이름 (수정 연필 아이콘 클릭 시 인라인 편집 가능).
   - 방 생성 일시 및 총 대화 수.
2. **참여 멤버 섹션 (Members)**:
   - 각 멤버의 원형 아바타, 이름, 역할 태그.
   - 각 멤버 옆 "1:1 대화로 이동" 액션 버튼.
   - "＋ 멤버 추가(초대)" 버튼 → 기존 방 멤버 선택 UI를 통한 동적 초대.
3. **단체방 운영 설정 (Room Settings)**:
   - **발언 선택 모드 (Speaker Selection)**:
     - `natural` (자연 발화: 멘션 우선 및 자연스러운 티키타카)
     - `list` (순차 발화: 목록 순서대로 돌아가며 발언)
     - `manual` (수동 호출: `@멘션`된 캐릭터만 발언)
   - **턴당 최대 반응 수** (1~5회 슬라이더 또는 옵션).
4. **하단 위험 구역 (Danger Zone)**:
   - "방 나가기" (목록에서 숨김/퇴장 확인 팝업).
   - "단체방 삭제" (방 및 방 세션 정리).

## 6. 하지 않는 것 (Out of Scope)

- 서버 측 방 메시지 프로토콜 및 `/api/rooms` 스키마 자체의 파괴적 변경.
- 음성 채팅 또는 WebRTC 스트리밍 연동.
- 읽음 확인(Read Receipts) 카운트 배지 추가 (단순성 유지 원칙).
- `app-shell.js` 파일 크기를 43,000 바이트 이상으로 팽창시키는 직접적 코드 추가.
