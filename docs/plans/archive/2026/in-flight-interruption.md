# 작업 중 즉시 개입/반영(In-flight Interruption & Steer) 아키텍처 및 구현 계획

- **작성일**: 2026-09-19
- **배경**: 실장님 피드백 ("작업중 메시지 입력하면 대기열 말고 진행중인 작업에 바로 반영할 수 없나? 클로드는 되는 것 같던데", "최대한 프로바이더별 이점을 살리는 쪽으로 진행해봐. 대기열에 넣는 건 무의미하지 싶네.")
- **목표**: 에이전트 작업 도중 유저가 메시지를 보낼 때, 의미 없는 큐잉(대기열 대기) 대신 프로바이더별 최적의 방식으로 **즉시 개입(Interruption & Steer)**하도록 전환.

---

## 1. 프로바이더별 실측 및 개입 메커니즘 SSOT

### A. Claude Code (`claude`)
- **실측 결과**: 
  - `stream-json` 입력 파이프가 열려 있어도 턴 진행 도중에는 추가 JSON 입력을 즉시 파싱하지 않고 블로킹됨.
  - 하지만 자식 프로세스에 **`SIGINT` 시그널**을 보내면 Claude Code 내부적으로 즉시 `[Request interrupted by user]`를 방출하고 턴을 안전하게 중단(Aborted)하며 세션 히스토리는 CLI 자체 DB에 그대로 남김.
  - 이후 동일한 `conversation_id`로 `--resume` 호출 시, 방금 전 중단된 지점까지의 컨텍스트를 유지한 채 새 유저 지시로 즉각 이어받음.
- **최적 전략**: 
  - 작업 도중 새 메시지 수신 시 -> 기존 자식 프로세스에 `SIGINT` 송신 -> 프로세스 종료/중단 대기 -> 방금까지 생성된 assistant 버퍼 보존 -> 새 메시지와 함께 즉시 재스폰(`--resume`).

### B. Antigravity CLI (`agy`)
- **실측 결과**:
  - `agy` 역시 장기 실행/루프 중 `SIGINT`를 수신하면 현재 턴(도구 호출/스트리밍)을 중단하고 종료됨.
  - `--conversation <id>` 플래그로 직전 컨텍스트가 유지됨.
- **최적 전략**:
  - `SIGINT`를 통한 즉각 중단 -> 현재 턴 텍스트 정리 -> 새 입력으로 즉시 재실행.

### C. Grok (`grok`) 및 One-shot CLI
- **실측 결과**:
  - One-shot 프로세스이므로 stdin이 없거나 닫혀 있음.
- **최적 전략**:
  - 실행 중인 subprocess `terminate()` -> 부분 텍스트 보존 -> 새 프롬프트로 즉시 재스폰.

### D. OpenAI Dialect / HTTP API (`omniroute` 등)
- **실측 결과**:
  - `self._http_resp` 소켓 닫기를 통해 스트리밍 즉각 취소 가능.
- **최적 전략**:
  - HTTP 연결 취소 (`stop()`) -> 부분 어시스턴트 텍스트 히스토리에 확정 -> 새 유저 턴으로 바로 HTTP 스트림 시작.

## 2. 세부 설계 및 수정 대상

### 1) `adapters.py` (프로바이더별 인터럽트 계약)
- `AgentAdapter.interrupt(proc)` 메서드 정의:
  - 기본: `proc.send_signal(signal.SIGINT)` (또는 `terminate()`)
  - 프로세스 종료 대기 및 안전 정리.

### 2) `session.py` (세션 코어 로직)
- `send()`에서 `self.busy`일 때의 동작 개편:
  - 기존: 무조건 `msg_queue.append()` 후 대기열 등록 이벤트 방출.
  - 변경:
    1. 샛길 질문(`/btw`)은 그대로 독립 스레드로 즉답.
    2. 일반 메시지인 경우:
       - 진행 중인 이전 턴을 **즉시 인터럽트(`self.interrupt_current_turn()`)**.
       - 직전까지 누적된 `self.current_text`가 있다면 이를 어시스턴트 히스토리에 부분 메시지(`[실장님 새 지시로 중단됨]`)로 안전하게 닫고 저장.
       - 대기열에 쌓지 않고 **새 메시지를 즉시 전송(`_send_direct(text)`)**.
       - SSE 이벤트로 `interrupted` 또는 `steered` 상태를 클라이언트에 실시간 알림.

### 3) `static/app.js` & `static/chat.css` (UI/UX)
- `updateSendButton()`:
  - 작업 중(`isBusy`)일 때의 버튼 문구를 `대기열 등록` -> `⚡ 즉시 반영 ↵` (또는 `끼어들기`)로 변경.
  - 사용자가 입력할 때 대기열이 아니라 현재 작업에 즉시 개입한다는 시각적 피드백 제공.
- `send()`:
  - `isBusy` 상태여도 대기열 표시 대신 일반 유저 메시지로 낙관적 렌더링하고 `setBusy(true)` 상태 유지.
  - 이전 어시스턴트 말풍선에 중단 배지 표시.

## 4. 2026-09-20 갱신 — 실측 결과와 최종 설계 (위 §1~§3의 "즉시 인터럽트"를 대체)

**문제**: §2의 설계는 진행 중인 턴을 곧바로 끊고 새로 시작했다. 실장님: "작업 도중에 메시지 보내면 하던 작업이 중단되는 것 같던데. claude처럼 작업은 계속 하면서 중간에 받아주는 게 아니었나." §1은 "끼워 넣기가 가능한가"를 시험하지 않았고, 게다가 당시에는 agy 대화 ID가 유령이라 끊고 재기동하면 에이전트가 맥락을 통째로 잃었다(agy.md A35·A36).

**실측 (agy 1.2.7)**: 도중에 stdin으로 쓴 메시지는 작업을 방해하지 않지만 **턴이 끝난 뒤에야** 처리된다(A41). 끼워 넣기 입력은 TUI에만 있고(A42), `agentapi`는 CSRF 토큰이 필요해 쓸 수 없다(A43). 즉 agy는 진짜 mid-turn 조종을 headless로 열어 두지 않았다.

**최종 설계 (agy, `AgySession._steer_*`)**: 스텝 경계에서 끼워 넣기.
1. 작업 중 메시지 → **즉시 접수**(`steer_queued` 이벤트, 화면에 바로 표시), 진행 중인 턴은 건드리지 않는다.
2. 도구 스텝이 하나 끝나는 순간(`step_update` tool DONE) 안전하게 자식을 멈추고 **같은 대화**(`--conversation <진짜 ID>`)로 즉시 재개. 다음 메시지 앞에 "취소된 게 아니니 이어서 하되 이 지시를 반영, 끝낸 단계를 다시 하지 마라"는 안내를 1회 붙인다(`STEER_HINT`). 경계당 메시지 하나, 나머지는 다음 경계로.
3. 경계가 오기 전에 턴이 끝나면 기존 종료 경로(`_dispatch_queued`)가 다음 턴으로 보낸다. 90초 동안 경계가 없으면(긴 추론 등) 타이머가 그때 끼워 넣는다.
4. 질문형(`?`)은 종전대로 `/btw` 옆길 답변. 이 경로들은 진행 중인 턴을 건드리지 않는다.

**agy 외 (claude/codex/grok/HTTP)**: 종전대로 즉시 인터럽트(§1)하되 위 안내를 붙여 "중단이 아니라 일시 정지"임을 알린다. 이 CLI들의 끼워 넣기 가능 여부는 이번에 실측하지 않았다(❓).

**실서버 검증**: `sleep 6`×3 작업의 첫 단계가 끝난 직후 새 지시를 보냈더니 같은 대화로 재개되어 남은 두 번만 실행하고 새 지시를 반영했다(총 3번, 처음부터 다시 하지 않음).

**부수 수정**: 끊고 재기동하는 사이에 옛 자식의 stdout 리더가 새 턴의 busy를 끄거나 옛 파이프의 잔여 줄을 새 턴 이벤트로 처리할 수 있어, `_read_stdout`이 자기 자식(`proc`)에 묶이도록 했다.

**한계**: 지연 = 다음 스텝 경계까지 + 재기동(약 3~10초). 접수 후 아직 반영 전인 메시지는 서버 재기동 시 사라진다(메모리 큐). 브라우저 화면 동작은 확인하지 못했다.
