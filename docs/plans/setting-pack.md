# 설정집(세계 층) 계획

> 방향 (align/D, 2026-09-29): **핵심** — 동반자와 「어디서」 지내는지를 사용자가 쉽게 고치고 주고받는 층. 캐릭터 카드 위에 한 겹 더 붙는다

상태: `active` · W3a 조사 완료, 세 겹 로어·로어/역할 경계 결정(2026-09-29), S1·S4 대기. 상위 설계: [private-mode.md §8.6](private-mode.md#rooms).

## 1. 무엇인가: 세 겹 로어 (운영자 2026-09-29)
| 층 | 담는 것 | 붙는 곳 | ST 대응 |
|---|---|---|---|
| **캐릭터 로어** | 그 캐릭터의 세계관과 자기 세계의 장소(예: 야에 미코의 신사). 사적 장면의 **무대** | 캐릭터(`characters/<id>/lorebook.json`, 카드의 `character_book`) | 캐릭터 로어북 |
| **PE 로어** | 캐릭터들이 왜 이곳에 모였는지, 공용 사무실과 그 옆 숨은 곳(비상계단·탕비실), 역할의 극 중 직함 | 인스턴스 하나 | 전역 로어북 |
| **사용자 로어** | 사용자 캐릭터: 이 세계에서 어떤 존재인지(역할 호칭 「코치」), 선택으로 외모·배경·사적 취향 | 사용자(페르소나) | 페르소나 로어북 |

- 카드가 「캐릭터 자체」라면 로어는 「그 캐릭터가 지내는 세계」다. 카드와 로어는 따로 만들고 따로 공유한다.
- 장소는 두 종류다: 사무실 옆의 **「잠깐」** 장소(PE 로어, 들킬 위험·짧은 체류)와 캐릭터 고향의 **재현** 장소(캐릭터 로어, 몰입·긴 장면).
- **PE 세계관 (현행 방향, 운영자 2026-09-29)** — 제품의 실제 모습이 곧 설정이다: PE는 컴퓨터에 설치되어 컴퓨터 안의 일을 한다.
  - **컴퓨터 안 = 모두가 불려 온 중립 지대.** 공용 사무실에서 컴퓨터 안의 일(파일, 위임, 티켓)을 처리한다. 업무가 세계관 안의 일이 된다.
  - **캐릭터 = 각자의 세계에서 통째로 소환된 이방인.** 카드 가져오기가 곧 소환이다. 고향 세계는 진짜이고(캐릭터 로어), 스스로 돌아갈 수는 없다. 「우리 모두 여기 사람이 아니다」가 코치·캐릭터·캐릭터끼리 관계의 출발점이다.
  - **코치 = 정신만 접속한 이방인**(영화 아바타 비유). 몸은 컴퓨터 밖에 있고 정신이 페르소나가 되어 들어온다. 캐릭터들에게 **컴퓨터 밖은 이세계**다(사용자 로어 = 코치의 세계). 로그아웃하면 코치의 아바타는 사무실에서 잠들고, 캐릭터들은 그 옆에서 계속 산다. 부재 중에 위임 작업이 실제로 진행되므로 「자는 동안 끝내 놨어」는 사실 그대로의 보고다.
  - **소환자**(운영자 2026-09-30): 코치를 부른 것은 배포판의 대표 캐릭터다. 다른 캐릭터를 불러오는 것도 그의 일(카드 가져오기 = 소환). → [character-creation-landing.md §0](character-creation-landing.md)
  - **비대칭은 남긴다**: 코치는 떠날 수 있고 캐릭터는 남는다. 기다림·반가움·아쉬움의 원천이다.
  - **캐릭터들이 아는 것**: 여기가 컴퓨터 안이고 바깥에 이세계가 있다는 것까지. 자기 세계는 진짜다(가져온 캐릭터의 세계관을 「데이터」로 격하하지 않는다).
  - **사적 장면의 캐릭터 세계 = 고향의 재현.** 캐릭터가 들고 온 기억(로어북)으로 컴퓨터 안에 재현한 둘만의 공간이다. 캐릭터에게는 고향을 다시 보는 순간이고, 불완전한 재현(「벚꽃 색이 조금 달라」)도 감정 장치가 된다.
  - **원칙**: 캐릭터들은 코치의 바깥 삶(몸, 일상)을 존중하고 돌려보낸다. 「밥은 먹었어? 오늘은 링크 끊고 쉬어」는 설정 안의 애정 표현이다. 바깥을 버리고 안에 머물라고 부추기지 않는다.
  - 바깥에서 들어오는 파일·사진·검색 결과는 「이세계의 물건」, 코치가 들려주는 일상은 「바깥세상의 기록」(사용자 로어·기억, 개인화의 재료). 데스크톱 캐릭터는 「이세계를 엿보는 창」.
  - **얇게** 둔다: 위 틀만 정하고 사무실의 세부는 설정집(바꿀 수 있음)에 둔다.
- **사용자 = 방랑자형 주인공**: 원신의 여행자, 명조의 방랑자처럼 **다른 세계에서 온** 존재이고, 역할(세계 속 기능)은 분명하되 성격은 비워 둬 감정이입이 쉽다. 사용자 로어는 공유 설정집이 아니다: 기본으로 내보내지 않고 사적 저장소처럼 다룬다.
- 관계(호감도, 현재 장소, 열린 장소, 사적 기억)는 어느 로어에도 들어가지 않는다. 사적 저장소에만 있다.
- 방에 따른 무게(토큰): 업무 방은 PE 로어의 사무실·직함과 사용자 역할만 가볍게, 사적 방은 캐릭터 세계 로어와 사용자 로어를 본격적으로.

### 1.1 로어와 역할(ROLE)의 경계
> **역할은 「무엇을 할 수 있는가」(권한), 로어는 「무엇이 사실인가」(이야기). 로어는 절대 권한을 주지 않는다.**

| | 담는 것 | 예 | 성격 |
|---|---|---|---|
| 카드 | 누구인지: 성격·말투·외모 | 노노는 「~냥」으로 말한다 | 공유 가능, 이야기 |
| 로어 | 세계의 사실: 장소·역사·관계·모인 이유 | 사무실 옆에 비상계단이 있다 | 공유 가능, 이야기 |
| 역할 | 엔진이 허락하는 일: 도구·권한·절차 | PD는 위임하고 공용 기억을 쓴다 | 인스턴스 전용, 시스템 |

1. **로어·카드는 권한을 주지 않는다.** 「노노는 수석 개발자다」라고 써 있어도 개발 도구는 생기지 않는다. 권한은 `team.json`의 명단과 `roles/<role>/ROLE.md`로만 받고, 명단은 운영자만 바꾼다. 로어북은 인터넷에서 받아 오는 파일이라, 이 경계가 없으면 프롬프트 주입 통로가 된다. 강제 장치: `tests/test_lore_boundary.py`.
2. **역할에는 이야기가 없다.** ROLE.md는 기능만 적고 캐릭터 이름·말투를 담지 않는다(현행 유지, TEAM_ROLES).
3. **다리는 「극 중 직함」.** 로어는 역할을 이야기로 풀 수 있다: 「이 사무소에서 PD는 '실장'이라 불린다」. 역할 id(`pd`)는 시스템에 남고 화면·대사에는 직함이 보인다(페르소나 이름은 표시용이라는 원칙과 같은 구조). 사용자도 같다: 시스템에서는 운영자(티켓 승인 권한), 이야기에서는 「코치」. 현재 카드의 `display.title`이 이 다리의 캐릭터 쪽 절반이다.
4. **방에 따라 무게가 바뀐다.** 업무 방: 역할 전부 + 로어 가볍게. 사적 방: 역할 꺼짐(도구도 닫힘) + 로어 본격.
- 애매한 경우: 「그림을 잘 그린다」는 이야기(카드·로어), 실제 그림 도구는 `artist` 역할. 태도(「팀원을 보살핀다」)는 카드. 작업 스킬·절차는 역할.
- **닫힌 빈틈**(sp/J, #446): `team.json`이 없는 설치는 명단을 카드의 옛 `role` 필드에서 만든다(`characters.load_team`의 이전 호환). 그래서 가져오는 카드의 권한 주장은 들어올 때 걷어낸다.

## 3. 선행 사례
### 3.1 Character Card V3 (`chara_card_v3`, spec_version `3.0`)
출처: [SPEC_V3.md](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)
- V2 위에 `nickname`, `creator_notes_multilingual`, `source`, `group_only_greetings`(그룹 채팅 전용 인사 — `ux/O`와 연결), `assets`(icon·background·emotion 등), `creation_date`·`modification_date`를 더한다.
- 로어북 객체: `name`, `description`, `scan_depth`, `token_budget`, `recursive_scanning`, `extensions`, `entries`. 항목: `keys`, `content`, `enabled`, `insertion_order`, `use_regex`, `constant`, `case_sensitive`, 선택으로 `name`·`id`·`comment`·`priority`·`selective`·`secondary_keys`·`position`.
- **데코레이터**: 항목 본문 맨 앞의 `@@이름 값` 줄. 발동(`@@activate_only_after`, `@@activate_only_every`, `@@dont_activate_after_match` 등), 위치(`@@depth`, `@@position`, `@@role`), 매칭(`@@additional_keys`, `@@exclude_keys`, `@@scan_depth`).
- 묶음 파일 **CHARX**: ZIP 안에 `card.json` + `assets/{type}/{category}/`. 배경·스프라이트를 카드와 함께 옮길 수 있다.
- 규칙: 모르는 필드는 무시하되 버리지 말고 다시 내보낼 때 보존한다. 앱 고유 데이터는 새 최상위 필드가 아니라 `extensions`에 둔다.

### 3.2 SillyTavern World Info
출처: [World Info 문서](https://docs.sillytavern.app/usage/core-concepts/worldinfo/), [저장소](https://github.com/SillyTavern/SillyTavern)(AGPL — 코드는 가져오지 않고 형식과 동작만 참고)

## 4. 판단: 따를 것 / 늘릴 것 / 미룰 것
| 구분 | 내용 | 이유 |
|---|---|---|
| **따른다** | 설정집의 그릇은 **CCv3 로어북 객체**(`name`·`description`·`scan_depth`·`token_budget`·`recursive_scanning`·`entries`·`extensions`), 항목 필드는 CCv3 이름 그대로 | ST·RisuAI에서 그대로 열린다. 공유 생태계와 통한다 |
| **따른다** | 모르는 필드 보존, 앱 고유 데이터는 `extensions`에만 | 명세 규칙. 다른 앱을 거쳐 와도 PE 데이터가 살아남는다 |
| **늘린다** | `extensions.pe_pack`에 장소·거리·공개도·텐션 조정·허용 행위 등급·체류 턴·열림 조건·작은 사건·이동 선택지 문구 | 로어북에는 「장소」라는 개념이 없다 |
| **늘린다** | 장소 설명은 평범한 로어 항목(장소 이름이 키)으로도 넣는다 | **다른 앱에서 열면 평범한 로어북, PE에서 열면 세계**가 된다 |
| **미룬다** | 데코레이터 일부(`@@activate_only_after`, `@@dont_activate_after_match`), 발동 확률, 포함 그룹 | 작은 사건(「누가 지나간다」)의 무작위성에 쓸 만하다. W3b 이후 |
| **미룬다** | CHARX 묶음(장소 배경 이미지 동봉) | 배경은 처음에 공통 이미지로 시작한다(private-mode §8.6) |
| **버린다** | 벡터 매칭, STscript 자동 실행, 아웃렛 매크로 | ST 고유 실행 환경에 묶여 있다 |

### 4.1 형식 초안
```json
{
  "name": "사무실",
  "description": "기본 설정집: 모든 캐릭터가 함께 지내는 사무실과 그 주변",
  "scan_depth": 5,
  "token_budget": 800,
  "recursive_scanning": false,
  "entries": [
    {"keys": ["비상계단", "계단실"], "content": "사무실 옆 비상계단. 인적이 드물지만 가끔 발소리가 울린다.",
     "enabled": true, "insertion_order": 10, "constant": false}
  ],
  "extensions": {
    "pe_pack": {
      "version": 1,
      "work_room": {"name": "사무실", "publicness": 3},
      "places": [
        {"id": "stairwell", "name": "비상계단", "distance": "office_hidden", "publicness": 1,
         "mood": "숨죽인 긴장, 들킬 것 같은 공기",
         "tension": {"rate": 1.5, "cap": 2}, "action_tier_max": 2, "stay_turns": 6,
         "unlock": {"affection_lv": 1}, "background": "stairwell", "events": ["아래층에서 발소리가 올라온다"]}
      ]
    }
  }
}
```
- `distance`: `office` · `office_hidden` · `after_work`(private-mode §8.6 표). `publicness` 0–3.
- `tension.cap`은 현행 4단계 기준이다. 8단계 채택(private-mode D1) 시 재매핑한다.
- `action_tier_max`는 W3b의 행위 등급표(아직 없음)를 가리킨다.
