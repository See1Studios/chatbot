## 2. 범위 / 비목표

**범위**
- 역할(디렉터)마다 허용 도구를 엔진이 집행한다.
- 저장소 변경을 도구 이름이 아니라 작업 트리 변화로 감시한다. 서브에이전트가 한 변경도 잡는다.
- 프로바이더별 서브에이전트를 실측하고, 어댑터 훅으로 연결한다. 공통 코드는 프로바이더 이름을 모른다.
- 디렉터 사이 넘기기: 기록, 자동 착수, 결과 보고, 횟수·예산 제한.

**비목표**
- 워크트리 위임·티켓·티어·교차 리뷰·운영자 머지를 대체하지 않는다. 코드 수정은 계속 그 길로 간다(D-2).
- 프로바이더 서브에이전트를 엔진이 직접 구현하지 않는다. CLI가 가진 것을 켜고 끈다.
- 사적 모드는 대상이 아니다. 넘기기와 서브에이전트는 업무 모드만 쓴다.

### 3.4 프로바이더 서브에이전트 (실측 2026-10-05, dir/C)

방법: 라이브 세션 밖 임시 git 폴더에서, 엔진 어댑터와 같은 출력 형식으로 각 CLI를 한 번씩 돌렸다. 과제는 "파일을 직접 읽지 말고 서브에이전트에게 `note.txt` 첫 줄을 읽혀 보고하라". 넷 다 서브에이전트를 띄웠고 정답을 돌려줬다.

| CLI (모델) | 호출 | 메인 턴 | 서브에이전트 안 도구 호출이 스트림에 | 읽기 전용으로 묶기 |
|---|---|---|---|---|
| agy 1.2.16 (flash-low) | `invoke_subagent`(유형·역할·모델 지정). 0.2초 만에 반환, 서브에이전트는 별도 대화 id | 안 끝남: 메인이 스스로 `schedule`·`manage_subagents`로 기다리고 서브에이전트 기록 파일을 읽었다(23초) | **안 보임.** 기록은 디스크(`~/.gemini/antigravity-cli/brain/<id>/…/transcript.jsonl`) | 미확인(유형 `research`의 제한 여부 모름) |
| claude 2.1.289 (haiku) | `Agent`. 어댑터의 `--allowedTools`에 없는데도 쓸 수 있었다. 백그라운드로 뜸 | 안 끝남: 완료 알림을 받고 이어서 답했다(17초) | **보임, 출처 구분됨**(`parent_tool_use_id`) | **됨, 허용 목록 방식만.** `Agent(general-purpose)`만 막으면 다른 유형(`claude`)으로 우회해 파일을 썼다. 쓰기 도구와 쓰기 가능한 유형을 모두 막고 읽기 전용 정의만 남기면 막혔다 |
| codex 0.154 (gpt-5.6-luna) | `spawn_agent` + `wait` | 안 끝남: `wait`로 기다림(20초) | **안 보임**(완료 메시지만) | 미확인 |
| grok 1.0.41 (기본) | `spawn_subagent`(background) + `get_command_or_subagent_output` | 안 끝남: 결과를 가져올 때까지(43초) | **보이지만 출처 구분 안 됨**: 서브에이전트의 `read_file`이 메인 호출처럼 나온다 | 설정으로 가능: `config.toml` 역할의 `default_capability_mode = "read-only"`, 내장 `explore`·`plan` 유형. 모델이 고르는 기본 유형은 무제한(`general-purpose`), 깊이 1 |

**설계에 주는 결론**

1. **어느 CLI도 서브에이전트가 도는 동안 턴을 끝내지 않는다.** "디렉터가 늘 대화를 받을 수 있게"는 서브에이전트가 아니라 엔진이 해야 한다: 진행 중 지시(steer)·`/btw`(이미 있음), 그리고 다른 디렉터에게 넘기기(dir/E–G, 별도 세션).
2. **엔진은 서브에이전트가 한 일을 도구 이벤트로 알 수 없다**(agy·codex 안 보임, grok 출처 없음). 저장소 변경 감시는 작업 트리 비교(dir/B)여야 한다.
3. **역할 권한(dir/A)을 내장 도구 이벤트로 막으면 grok에서는 서브에이전트의 읽기까지 디렉터의 읽기로 보여 막힌다.** dir/A의 내장 도구 차단은 시작 인자로 막을 수 있는 프로바이더(claude 허용 목록)에만 쓰고, 나머지는 엔진 도구 거절 + dir/B로 지킨다.
4. **읽기 전용 서브에이전트는 claude(허용 목록)와 grok(설정 역할)만 확인됐다.** agy·codex는 미확인이라 D-2대로 코드 수정은 워크트리 위임만.

## 6. 의존 · 순서 · 리스크

- 순서: dir/H, dir/C(코드 변경 없음) → dir/I, dir/J(걷어내기) → dir/A, dir/B(집행) → dir/D → dir/E → dir/F → dir/G.
- 경고만 하는 가드는 이 계획이 끝나면 남기지 않는다: `write_guard.py`는 dir/B로 차단이 되고, 역할 `tools:`는 dir/A로 집행이 된다.
- **리스크: 서브에이전트 사각지대.** dir/B가 끝나기 전에는 서브에이전트가 본 트리를 고쳐도 모른다. 그때까지 업무 모드의 서브에이전트는 쓰지 않는다(운영자 시험 호출 제외).
- **리스크: 쿼터.** 넘기기마다 디렉터와 서브에이전트가 쿼터를 쓴다. D-4 한도 + `tools/run_usage.py`와 같은 정의로 넘기기 단위 사용량을 남긴다(token-economy T6·T7과 같은 표에서 비교).
- **리스크: 약한 두뇌의 판단.** 넘길지 말지를 모델에 맡기면 오늘처럼 맞장구와 지어내기가 나온다. 대상 고르기·한도·권한은 엔진이 정하고(engine-decides), 모델은 "넘긴다/직접 한다"와 할 일 문장만 쓴다.
- **⚡:** dir/A·B·D·E·F·G는 호스트 모듈을 바꾼다. 재기동은 운영자가 쉬고 있을 때나 동의할 때만.
