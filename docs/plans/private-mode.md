<a id="action"></a>
## 1. 액션·동적 선택지

목적: 행위(스킨십·동작·연출)를 타이핑 없이 고르고, 말풍선과 지문을 분리하고, 다음 턴에도 감정선·물리 상태가 이어지게 한다.

### 1.1 표시 vs 컨텍스트

| 구분 | 컨텍스트(모델이 보는 기록) | 화면 |
|---|---|---|
| 사용자 말 | `"오늘 힘들었어"` | 사용자 말풍선 |
| 사용자 액션 | `(머리를 쓰다듬는다)` 또는 `type: action` 이벤트 | 말풍선 없음, 은은한 지문 |
| 캐릭터 액션 | `*얼굴을 붉힌다*` | 나레이션 지문(이탤릭 의도 — 현재 스타일 없음, §5) |
| 캐릭터 대사 | `"..."` | 메인 말풍선 |
| 속마음 | ` ```thought ` 펜스(파서는 `<thought>`도 수용) | 접이식 `.thought-box` |
| 표정 | 첫 줄 `[expression: neutral\|joy\|shy\|serious\|sorrow\|tired]` | `.exp-badge` |

### 1.2 렌더 계약 (구현: `RENDER_PROTOCOL`, 사적 지침 묶음에 포함)
- 행동·시선·몸짓은 `*...*`, 발화는 `"..."`. 1–2문장, 소설체·메타 발언 금지.
- 표정 태그는 맨 앞, 속마음은 ` ```thought ` 블록.
- 매 답 끝에 `<!--choices: 라벨 -> "대사" | 라벨 -> (행동) | 라벨 -> "대사" (행동)-->` 2–4개. 대사형·행동형·혼합형을 상황에 맞게 섞는다.
- 사용자가 행동 선택지를 누르면 말풍선 없이 `(행동)`이 주입된다(`/act`).

### 1.3 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | `->` 파싱, 표정 뱃지, 속마음 토글, `/act` (#130) | 구현됨 |
| 2 | 사적 지침·카드에 행위 지시문·예측 선택지 규칙 주입 | 구현됨(#164 `RENDER_PROTOCOL`) |
| 3 | 선택지·액션을 `choices` 도구·`action` 이벤트로, 기록·요약 시 액션 상태 보존 | [out-of-band-choices-actions.md](out-of-band-choices-actions.md)로 대체 |
| — | 실사용 테스트·지문/대사 티키타카 품질 튜닝 | 계획 |

<a id="tension"></a>
## 2. 텐션 엔진

문제: 선택지가 1턴 수준(쓰다듬기·안아주기)에서 맴돌고, 거리감의 단계 추적이 없고, 선택지 온도차가 없다.

### 2.1 현행 4단계 vs 8단계 초안

| 항목 | 현행 (구현됨, `private_engine.py`) | 8단계 초안 (2026-09-26, PD 입안) |
|---|---|---|
| 상태 | `tension_stage` 정수 1–4, 세션 `meta.json` 저장 | `tension_score` 0–100 + `tension_phase` 0–7 |
| 단계 이름 | 계열별 데이터: defaults `도입/교감/친밀/깊은 유대`, gemini `도입/고조/밀착/절정` | 정적 0–9 · 감응 10–24 · 접촉 25–39 · 고조 40–54 · 심화 55–69 · 고원 70–84 · 돌파/결합 85–94 · 절정·여운 95–100 |
| 슬롯 | 3슬롯: 0 유지 / 1 +1 / 2 +2 (라벨·가이드는 JSON) | Slot1 +1~3 / Slot2 +5~8 / Slot3 +10~15 |
| 액션 입력 | `(…)` 또는 `type: action` → +1 | +5 |
| 일반 대화 | 유지 | +0 |
| 하강 | 없음(클램프만) | 없음 |
| 제동 | 없음 — 슬롯 2를 두 번 누르면 1→4 | T<40에서 턴당 +12 상한 → 최소 4–6턴 빌드업 |
| 행위 허용 | 단계 이름·분위기 문장만 | 페이즈별 허용 행위, 도구/자세는 페이즈 0–3 절대 금지, 4 자세 전환, 5 소품 준비, 6 전면 해금, 7 피니시·후희 |
| 최근 선택지 | `recent_choices` 최대 9개, 중복 제거 | 동일(반복 금지 줄) |
| 컨텍스트 | `[Tension Engine Context]` Stage n/4 + 분위기 + 반복 금지 + 3슬롯 계약(`tension_context`) | `Phase p/7 [Score s/100]` + 분위기 + 제약 규칙 + 슬롯별 목표 점수 |
| 계열별 표 | `FAMILY_FILES`(gemini만 자체 표), 없으면 defaults | 두 JSON 모두 8페이즈로 갱신 |
| 파일 | `private_engine.py`, `engine_data/private_tension_{defaults,gemini}.json`, `session.py`, `tests/test_private_tension.py` | 같음 |

충돌은 풀지 않는다 → §6 D1–D4.

### 2.2 원래 4단계 계획 중 코드와 다른 부분 (보존)
- 슬롯 성격: A 밀당/장난(유지·튕기기) · B 반 발짝 전진 · C 직진/도발(다음 단계로). 현 코드 슬롯은 "유지·전진·깊은 교감"으로 밀당 슬롯이 없다.
- 밀당/화제전환 선택이나 긴 쉼 → 단계 유지 또는 완만한 완화. 현 코드엔 완화가 없다.
- 선택지 검증: 상투적 선택지면 경고·필터(미구현). 반복 금지 창은 원안 "최근 3턴", 코드는 최대 9개.
- 카드 동기화: 캐릭터 카드 사적 지침에 슬롯 규격 반영(현재는 공통 `RENDER_PROTOCOL`+JSON이 담당).

## 3. 영구 호감도

> 관련(설계): 진행·약속·선호·금기 등 **서술형 관계 연속**은 [character-memory-adapter.md](character-memory-adapter.md). 본 절 호감도·텐션 수치 엔진과 중복 설계하지 않는다.

목적: 세션 텐션은 새 세션마다 초기화된다. 캐릭터별 누적 유대를 정량 저장해 첫 인사 톤·시작 텐션·속마음 개방도·특별 상호작용을 해금한다. 노가다 없이 대화만으로 서서히 성장.

### 3.1 등급
| Lv | 관계 | pt | 시작 텐션 | 반응 | 해금 |
|---|---|---|---|---|---|
| 1 | 어색한 동료 | 0–19 | Stage 1 | 정중, 터치에 경계 | 기본 대화 |
| 2 | 친밀한 파트너 | 20–49 | Stage 1 | 가벼운 장난·접촉 호의 | 가벼운 스킨십 지문 |
| 3 | 특별한 호감 | 50–79 | Stage 2 | 시작부터 긴장감, 솔직한 속마음 | Stage 2 직행, 질투/애교 |
| 4 | 깊은 연인 | 80–99 | Stage 2–3 | 경계 0, 적극 호응 | 농밀한 슬롯 우선, 전용 애칭 |
| 5 | 완전한 유대 | 100 | Stage 3 | 무조건적 신뢰, 독점욕 | 히든 선택지·전용 지문 |

### 3.2 저장
- `characters/<id>/state.json` 또는 `card.json` `extensions.chatbot.private.affection`(§6 D6). Git 비추적, `private-memory.md` 옆.
- 스키마: `{"affection": {"points", "level", "title", "interactions_count", "last_updated", "milestones": []}}`. 세션 종료 시 원자적 저장.

### 3.3 성향(disposition) — `card.json` `extensions.chatbot.disposition`
같은 행동이 성향에 따라 +/−로 갈린다(예: 벽으로 밀치기 — 신중형 −3, 대담형 +2, 순종형 +3; 일 칭찬 — 신중형 +3, 대담형 −1; 볼 꼬집기 — 신중형 −2, 대담형 +2, 순종형 −1).

| 키 | 형태 | 뜻 |
|---|---|---|
| `traits` | 문자열 목록 | 성향 태그 |
| `axes` | pace·expression·initiative·boundary·focus, −1.0~+1.0 | 템포·표현·주도권·거리감·갈망 |
| `sensual` | libido 0–1, dynamics −1(순종)~+1(지배), kiss_intensity 0–1 | 사적 무드 역학 |
| `erogenous_zones` | 부위 → {sensitivity, reaction} | 민감 부위 반응 |
| `kinks` / `taboos` | {tag, desc, weight ±} | 선호(+) / 기피(−) |
| `triggers` | 이름 → {delta, reason} | 직접 증감(예: craft_praise +3, patient_waiting +2, abrupt_skinship −3) |

### 3.4 증감·반응
- 모델이 매 턴 `[affection: ±N, tag]`(또는 `[affection: 0]`)을 낸다. UI는 숨기고 게이지 `+N/−N` 애니메이션.
- 상승: joy/shy 표정, 속마음 개방, 더 과감한 선택지. 하락: serious/sorrow/tired, 물러나는 지문, 방어적 선택지.
- 누적 감점이면 레벨 강등 가능. 사과·배려 행동에 회복 보너스 +2.
- 고단계(Stage 3–4)에서만 `erogenous_zones`·`kinks`를 JIT 주입(신체 반응 지문, 슬롯 3 탐닉 선택지). Stage 1–2는 축 기반 태도 1–2줄만(토큰 절약). 수치(−1.0~1.0)는 노출하지 않고 자연어 1–2줄로 합성(Chub Lorebook·BetterSimTracker 방식).

### 3.5 흐름
세션 시작 → 호감도 로드 → Lv로 `base_stage`·태도 결정 → `[Affection & Disposition Context]` 주입 → 턴마다 텐션 상승, Stage 3+에서 부위·취향 활성화 → 세션 종료 시 포인트 정산·저장.

### 3.6 단계
1. 백엔드: `state.json` 읽기/쓰기, 계산 함수, 텐션 컨텍스트에 결합 (`characters.py`, `private_engine.py`).
2. 세션 연동: 시작 시 기본 텐션 로드, 턴·종료 시 정산 (`session.py`).
3. UI: 상단 하트/레벨 뱃지, 시작 분위기 문구, 레벨업 토스트(§4).

| 사적 CSS는 두 줄뿐(`.meta`, `#input` 색) | `static/chat-features.css` (`body.private-session`) |
| `RENDER_PROTOCOL`은 행동 `*이탤릭*`, 대사 `"따옴표"`를 요구하나 `.md em` 스타일이 없고 한글 폰트엔 진짜 이탤릭이 없어 모바일에서 지문과 대사가 똑같이 보임 | `private_engine.py::RENDER_PROTOCOL` |

### 5.2 설계
- 공용 코어 하나 + 모드별 데코레이터: `registerDecorator({id, modes, run(node, raw, isFinal)})`.
- `postProcessAssistant`는 현재 모드를 **한 곳**에서 읽어 해당 데코레이터만 실행.
- 파일: `static/render-work.js`(highlight, mermaid), `static/render-private.js`(expression, thought, 이후 나레이션·HUD).
- 사적 스타일은 전부 `body.private-session` 아래로 스코프. 프로바이더 이름 금지.

### 5.3 단계 (단계당 티켓 1개)
| 단계 | 내용 |

## 8. 두 방의 관계와 장소

> 결정 (운영자, 2026-09-29): 한 캐릭터의 두 방. 저장·기억은 완전히 분리하고, 전환은 끊기지 않은 느낌으로 한다. 텐션·게임 장치는 사적 방 전용.
> 계기: 업무 방에서 애정 표현이 오갔고 그것이 사적 방까지 이어졌는데, 「하면 안 되는 곳에서 선을 넘는」 느낌이 오묘하고 긴장되며 좋았다. 그 효과를 누출이 아니라 설계된 장치로 재현한다.

### 8.1 현재 사실 (코드)
- 세션은 캐릭터 × 모드로 나뉜다. `/private on|off`가 방을 바꾼다(`server.py`, `REG.get_private`/`REG.get_active`).
- 사적 방을 나가면 대화가 `private-memory.md`로 요약된다(`_digest_private_later`). 업무 방은 그 파일을 읽지 않는다.
- **방문마다 새 세션**(PRIVATE_VISIT_v1, #440, 운영자 2026-09-29): `/private on`과 캐릭터 전환으로 사적 방에 들어갈 때마다 새 사적 세션을 연다(`get_private(fresh=True)`). 이전 장면의 장소·대화가 다음 방문에 새지 않는다. 이어지는 것은 사적 기억 요약(`private-memory.md`)과 호감도뿐이다. 두뇌는 직전 사적 세션의 것을 이어받고, 아직 한마디도 없는 직전 세션은 새로 만들지 않고 다시 쓴다. 알려진 틈: ① 나가자마자 다시 들어가면 요약이 아직 안 끝나 방금 방문이 기억에 없을 수 있다 ② 사적 모드에서 캐릭터를 바꾸면 떠나는 사적 세션은 요약되지 않는다.
- 사적 세션은 업무 기억·관찰·티켓에서 제외된다(PRIVATE_CLOSED). 사적 방에서는 위임할 수 없다.
- 텐션은 세션마다 초기화된다(`private_engine`). 장소 개념은 없다. 캐릭터마다 배경(`stage.webp`) 한 장이 있을 뿐이다.

### 8.2 방향 규칙
| 방향 | 넘어가는 것 | 넘어가지 않는 것 |
|---|---|---|
| 사적 → 업무 | 없음. 돌아올 때의 **장면 지문**(어디에 다녀왔는지 한 줄, §8.5)만 | 대화 원문, 사적 기억, 호감도, 텐션, 장소 상태 |
| 업무 → 사적 | **문턱 인계**(§8.4): 사건 표시와 1–3문장 요지. **끼어들기 신호**(§8.6) | 업무 원문, 업무 기억, 파일, 도구, 스킬 목록 |

업무 방의 캐릭터는 사적 방에서 있었던 일을 모르는 척하는 게 아니라 **실제로 모른다**. 화면에서는 「아무 일 없었던 척」으로 읽힌다.

### 8.3 업무 방 = 사무실
- **사무실은 모든 캐릭터가 함께 지내는 공간이다** (운영자 2026-09-29). 만든 캐릭터는 모두 기본적으로 사무실에 있다(팀 역할 구조와 같은 곳). 사적 장소는 기본적으로 운영자와 **캐릭터 한 명**의 공간이다. 나중에는 사적 장소에도 여러 캐릭터가 함께할 수 있다(운영자 2026-09-29, [ux-shell-roadmap.md](ux-shell-roadmap.md) `ux/O`). 그때도 원칙은 같다: 사적 기억은 **그 자리에 있던 캐릭터에게만** 남고, 사무실과 자리에 없던 캐릭터에게는 넘어가지 않는다.
  - 그래서 사무실의 공개도는 실제다: 다른 캐릭터가 보는 곳에서 선을 넘는 것이 긴장의 원천이 된다.
  - 열린 질문(결정 필요, §6에 올림): 사무실에서의 애정 표현을 **다른 캐릭터가 목격하고 반응**하게 할지(질투, 눈치, 소문). 한다면 넘어가는 것은 「무슨 일이 있었다」는 사건 표시까지이고, 사적 장소의 내용은 절대 아니다.
- 캐릭터는 애정 표현을 알아채고 **당황하며 짧게 받은 뒤 일로 돌아간다**. 완전히 거절하지도, 다 받아 주지도 않는다. 이 동작은 업무 지침 한 줄로 둔다.
- 업무 방에는 텐션·호감도·장소 장치가 없다.
- 애정 턴은 **업무 기억·관찰·티켓 대상에서 빠진다**(대화창에는 남는다). 판정(W1, #427): 채팅 에이전트가 `personal_turn` 도구로 그 턴을 표시한다(`personal_turn.py`, PERSONAL_TURN_v1). 표시된 턴 동안 업무 도구(memory·observation·ticket·delegate·web)가 닫히고, 관찰 후보가 되지 않으며, 업무의 과거 대화 검색(`recall_memory.py`)에서 빠진다. 같은 검색은 사적 세션을 통째로 제외한다(이전에는 사적 세션도 검색됐다). 업무 방 안의 이어짐(세션 인계 요약)은 그대로 둔다: 같은 방 안의 기억이다. 모델이 표시를 빠뜨리는 경우는 남는다. 실사용에서 자주 빠지면 가벼운 분류기를 더한다.
- 애정 턴이 있으면 「선을 넘을 뻔함」 사건 표시(내용 없음, 시각만)를 남긴다. 캐릭터는 「이런 얘긴… 둘만 있을 때」라며 사적 방으로 초대할 수 있다.
- **장소 이동 선택지** (운영자 제안 2026-09-29): 분위기가 야릇해지면 업무 방 답변 끝에 이동 선택지가 뜬다(예: 「잠깐 계단실로…」 / 「퇴근하고 봐요」 / 「일 계속하기」). 기존 선택지 채널(`choices` 도구, 선택지 칩)을 쓴다. 이동을 고르면 `/private on`과 같은 전환이 일어나고, 고른 장소가 사적 방의 첫 장소가 되며, 사건 표시와 함께 문턱 인계(§8.4)가 시작된다. 「일 계속하기」가 항상 있고, 연달아 거절하면 한동안 다시 제안하지 않는다.
  - 구현(W2b, #430): `personal_turn` 도구의 답이 이동 제안 여부를 알려 준다. 30분 안에 이동 없이 표시된 턴이 2번을 넘으면 제안하지 않고, 사적 방으로 이동하면 다시 센다(`personal_turn.offers_left`). 선택지는 `라벨 -> command: /private on <장소>` 버튼이고 `/private`는 허용 명령이다.

### 8.4 문턱 인계 (업무 → 사적)
- 사적 방에 **들어가는 순간 한 번만** 주입한다: 사건 표시가 있으면 그것, 없으면 최근 업무 맥락의 캐릭터 시점 요지 1–3문장(예: 「방금 배포를 끝내고 지쳐 보였다」).
- 사적 방의 첫마디가 그것을 받아 시작한다. 사건 표시가 있으면 시작 텐션이 한 칸 높다.
- 세기 설정: 끔 / 분위기만 / **요지(기본)**. 캐릭터별로 둔다.
- 구현(W2, #430): `threshold.py` THRESHOLD_v1. `/private on [장소]`로 들어갈 때 `threshold.enter`가 쪽지를 `<sessions>/<사적 sid>/threshold.json`에 남기고, 사적 방 첫 턴에 `private_engine.turn_context`가 한 번 꺼낸다. 직전 업무 턴이 30분 안의 사적인 턴이면 「brink」(내용 없음, 텐션 +1), 아니면 2시간 안의 업무 대화 요지(한 번의 요약 호출, 경로·링크·코드가 든 문장은 버림, 사적인 턴은 요약 입력에서 제외). 세기는 `characters/<id>/state.json`의 `threshold`(off|mood|gist, 기본 gist). 설정 화면은 아직 없다.

### 8.5 장면 지문 (양방향, 운영자 2026-09-29 — 「여운」 기분 태그를 대체)
- 방을 바꾸는 것은 큰 장면 전환이다. 전환 직후 **캐릭터가 먼저 반응**하도록, 엔진이 장면 지문 한 줄을 행동(`/act`, `type: action`)으로 보낸다. 사용자가 먼저 말할 필요가 없다.
  - 들어갈 때: 「(업무 도중 잠깐 함께 비상계단에 왔다)」 — 장소가 없으면 「(잠깐 둘만 있을 곳으로 함께 자리를 옮겼다)」, 최근 업무가 없으면 「업무 도중」을 뺀다. 문턱 인계 쪽지(§8.4)가 이 첫 턴에 함께 실린다.
  - 돌아올 때: 「(함께 비상계단에서 사무실로 돌아왔다)」 — **어디에 다녀왔는지만** 넘어간다. 사적 방에서 한 말, 기억, 호감도, 텐션은 넘어가지 않는다(§8.2). 업무 방 캐릭터는 이 한 줄로 상황을 알아채고 시치미·헛기침 같은 반응을 스스로 만든다.
- **기본 켬**. 캐릭터별 `state.json`의 `auto_scene: false`로 끈다.
- 구현(#431, SCENE_v1): `threshold.enter`/`threshold.leave`가 지문을 정하고 전환 응답의 `scene`으로 돌려주면, 페이지(`applyModeSwitch`)가 `sendAction`으로 보낸다. 서버가 직접 턴을 시작하지 않는 이유: 오래 쉰 세션은 보내는 순간 새 세션으로 넘어갈 수 있는데, 페이지 경로는 그 전환을 이미 처리한다. 장소는 사적 세션 폴더 `scene.json`에 두었다가 돌아올 때 쓰고 지운다. 요지 쪽지가 아직 만들어지는 중이면 첫 턴이 최대 12초 기다리고, 그보다 늦은 요지는 버린다(다음 턴에 엉뚱하게 끼지 않게).

### 8.6 장소 층 (사적 방)
장소는 사무실을 기준으로 한 **거리**로 나눈다.

| 거리 | 예 | 성격 |
|---|---|---|
| 사무실 | 업무 방 | 공개. 참아야 하는 곳 |
| 사무실 안 숨은 곳 | 계단실, 탕비실, 옥상, 빈 회의실 | 근무 중. 들킬 위험 때문에 텐션이 빨리 오르지만 상한이 낮다. 체류 턴 제한(「이제 들어가야 해요…」) |
| 퇴근 후 | 퇴근길, 카페, 캐릭터의 방, 캐릭터 고향의 재현([setting-pack.md §1](setting-pack.md)) | 여유가 있고 깊어진다. 공개도에 따라 속도와 상한이 다르다 |

- 장소마다 정하는 것: 배경, 분위기 한 줄(프롬프트에 주입), 텐션 속도와 상한, 공개도, 작은 사건(「누가 지나간다」).
- **행위 제약** (운영자 2026-09-29, 몰입도): 장소마다 허용 행위 등급이 있다(예: 계단실 = 손잡기·짧은 포옹까지, 카페 = 대화·가벼운 접촉, 방 = 제한 없음). 엔진이 강제한다. 프롬프트로 부탁하는 데서 끝나지 않는다.
  - 액션 메뉴와 선택지는 장소의 허용 등급으로 걸러진다.
  - 자유 입력으로 선을 넘으면 캐릭터가 장면 안에서 막는다(「여기선 안 돼요… 누가 보면 어떡해요」). 공개도가 있는 장소에서는 들킬 위험이 오른다.
  - 장소를 옮기는 이유가 생긴다: 「여기서는 더 못 하니 자리를 옮긴다」가 게임의 동력이 된다.
  - 텐션 상한(장소별)과 허용 행위 등급은 한 표(`engine_data/places.json` 가칭)에서 함께 정한다.
- 목록: **공통 기본 장소 + 캐릭터 카드의 전용 장소**(예: 신사). 일부 장소는 호감도 레벨로 열린다.
- 이동은 선택지나 대화로 한다. 배경이 바뀌고 장면 전환 한 줄이 나온다. 사무실에서 넘어오면 첫 장소는 사건에 맞춘다(근무 중이면 계단실, 퇴근 후면 퇴근길).
- 현지 시간대가 분위기와 배경을 바꾼다(밤 옥상, 아침 카페).
- 배경은 처음에 장소별 공통 이미지 몇 장으로 시작하고, 캐릭터 전용 배경은 그림 위임으로 나중에 채운다.
- **끼어들기**: 사적 방에 있는 동안 실제 업무 사건(위임 완료, 승인 요청)이 생기면, 사무실 안 장소에서는 「누가 올라오는 소리」나 「사무실에서 부르는 것 같아요」로 나타난다. 신호만 넘기고 내용은 넘기지 않는다.
- **설정집 = 공유 가능한 데이터** (운영자 2026-09-29): 장소, 허용 행위 등급, 텐션 속도·상한, 작은 사건, 이동 선택지 문구는 코드가 아니라 사용자가 쉽게 고치고 주고받는 설정집(JSON 한 파일)에 둔다. 가져오기·내보내기는 파일 하나로 끝난다.
  - 코드 참고: [SillyTavern 저장소](https://github.com/SillyTavern/SillyTavern) — World Info(로어북) 형식·삽입 규칙, 캐릭터 카드 V2/V3 읽기, 그룹 채팅 발화 순서(`ux/O`)의 원본 구현(운영자 2026-09-29). 라이선스(AGPL) 때문에 코드는 가져오지 않고 형식과 동작만 참고한다.
  - 시장 참고: [OpenRouter의 SillyTavern 앱 페이지](https://openrouter.ai/apps/sillytavern) — ST 사용자들이 실제로 쓰는 모델과 사용량(운영자 2026-09-29). 기본 두뇌 추천과 설정집이 어떤 모델에서 잘 동작해야 하는지 판단할 때 본다.
  - 선행 사례부터 본다(구현 전 조사): **Character Card V3**(`chara_card_v3`, RisuAI 쪽에서 낸 명세. 로어북 데코레이터, 에셋, CHARX 묶음 파일 등 — 원문 확인 필요. 엔진은 지금 V2만 읽는다: `characters.py` SPEC), Character Card V2의 `character_book`, SillyTavern World Info(로어북) 가져오기·내보내기, Chub 로어북. 형식을 따를 수 있으면 따라 기존 공유 생태계와 통하게 한다.
  - **카드 위에 한 겹 더 붙는 층** (운영자 2026-09-29): ST 캐릭터 카드가 「캐릭터 자체」라면 설정집은 「그 캐릭터와 지내는 세계」다. 카드와 설정집은 따로 만들고 따로 공유하며, 아무 카드나 아무 설정집에 넣을 수 있다(같은 캐릭터를 사무실 설정집에도, 학교 설정집에도).
  - 「업무 방 = 사무실」도 기본 설정집의 한 해석이다. 업무 방이라는 기능은 엔진에 있고, 그 방을 어떤 장소로 부를지(사무실, 연구실, 동아리방)와 옆의 숨은 곳들은 설정집이 정한다.
  - **카드로 자동 생성** (운영자 2026-09-29): 캐릭터 카드를 읽고 AI가 어울리는 설정집 초안을 만드는 옵션(예: 야에 미코 → 신사 경내, 배전 뒤편, 사쿠라 나무 아래). 결과는 사용자가 고칠 수 있는 초안 파일이다. 저장 전에 설정집 형식 검사를 그대로 통과해야 한다. 생성에는 카드만 입력으로 쓰고, 사적 기억이나 호감도는 넣지 않는다.
  - 엔진은 기본 설정집(사무실) 하나를 제공한다. 캐릭터 카드는 어울리는 설정집을 **추천**만 할 수 있고, 품지는 않는다(층을 섞지 않는다).
  - **설정집에는 관계가 들어가지 않는다**: 호감도, 현재 장소, 열린 장소, 사적 기억은 사적 저장소에만 있다(D6과 같은 원칙: 카드는 공유 가능, 관계는 아님). 공유 파일에 개인 기록이 섞이지 않는 것을 테스트로 막는다.
- 장소 상태(현재 장소, 열린 장소, 마지막 장소)는 사적 저장소(호감도와 같은 곳, D6)에 둔다.

### 8.7 단계와 강제 장치
규칙마다 테스트나 게이트를 하나씩 둔다.

| 단계 | 내용 | 강제 장치(테스트) |
|---|---|---|
| W1 | 사적 → 업무 격리 점검. 업무 방 애정 턴을 업무 기억·관찰·티켓에서 제외 | 업무 지침 묶음에 사적 기억·호감도·장소가 없음. 애정 표시 턴이 관찰·요약 입력에서 빠짐 |
| W2 | 문턱 인계(사건 표시, 요지, 세기 설정) | 진입 첫 턴에만 한 번 주입됨. 업무 원문·파일 경로·스킬 목록이 들어가지 않음. 끔이면 아무것도 없음 |
| W2b | 업무 방 장소 이동 선택지(§8.3) | 이동 선택지가 사적 전환 + 첫 장소 지정으로 이어짐. 「일 계속하기」가 항상 포함됨. 거절 후 쿨다운 동안 다시 나오지 않음 |
| W3 | 장소 층(데이터, 이동, 배경, 시간대, 텐션 조정, 열림 조건) | 장소 상태가 사적 저장소에만 쓰임. 업무 방 요청에서 장소를 읽지 않음. 장소별 상한이 텐션 계산에 적용됨 |
| W3a | 설정집 형식(선행 사례 조사 ✅ [setting-pack.md](setting-pack.md) → 형식 결정 S1–S4 → 가져오기·내보내기 sp/C) | 내보낸 파일에 사적 저장소 키가 없음. 잘못된 설정집은 짧은 오류로 거절됨 |
| W3c | 카드 기반 설정집 자동 생성(초안) | 생성 결과가 형식 검사를 통과해야 저장됨. 생성 입력에 사적 저장소 내용이 없음 |
| W3b | 장소별 행위 제약 | 허용 등급 밖의 액션이 메뉴·선택지에 나오지 않음. 금지 행위 입력 시 엔진이 거절 맥락을 주입함 |
| W4 | 끼어들기(업무 사건 → 장소 속 신호) | 신호에 티켓 제목·본문이 들어가지 않음 |
| W5 | 장면 지문(양방향, 기본 켬) — #431 ✅ | 돌아오는 지문에 장소 외 내용이 없음. 지문은 한 번만 쓰임. 끄면 지문 없음. 늦은 요지는 버려짐 |
